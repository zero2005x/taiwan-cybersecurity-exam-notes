## 一、數位鑑識（25 分）

**題組敘述**：請回答下列有關數位鑑識之問題。

### （一）何謂資料採集（15 分）

**阿摩查核**：

- [申論頁 519330](https://yamol.tw/exam/122014?info=essay.519330)：一起撐住一起上榜，2025-11-12，詳解 7075949，標示由 ChatGPT 產生，付費，已解鎖查核，有幫助 3／沒幫助 0

**題目**：(一)在數位鑑識（Digital Forensics）標準作業程序中，何謂資料採集（Data Acquisition）？（15 分）

**網友主解摘要與查核**：一起撐住一起上榜（標示 ChatGPT）定義為完整、可驗證、不改變原件的複製，提到映像、雜湊與監管鏈，正確但偏簡略；採為主解，補採集類型、揮發性順序與注意事項。

**整理者補寫**：資料採集是鑑識流程「識別、採集（保全）、檢驗、分析、報告」中的取得步驟，指以鑑識上可靠的方法，從電腦、行動裝置、雲端或網路蒐集數位資料並製作可驗證的副本，確保證據完整、可重現且合法取得。

1. **類型**：靜態採集（關機後拆下儲存媒體，用寫入保護器製作逐位元映像）；即時採集（系統運作中擷取記憶體、網路連線、已解密磁碟區）；邏輯採集（只取特定檔案、信箱或雲端帳號資料）；網路採集（側錄封包、調閱日誌）。
2. **要領**：依揮發性順序（暫存器與快取、記憶體、網路狀態與程序、暫存檔、磁碟、遠端日誌、備份媒體）先取最易消失者；使用寫入保護、經驗證的工具；製作映像後計算 SHA-256 等雜湊，原件與副本比對一致；全程記錄時間、人員、工具版本、步驟並填寫證據監管鏈；在搜索扣押範圍內取得，必要時取得同意或令狀；加密磁碟要在關機前判斷是否需即時取得金鑰。

### （二）確保數位證據完整性應優先採取的行動（10 分）

**阿摩查核**：

- [申論頁 519331](https://yamol.tw/exam/122014?info=essay.519331)：nomi，2024-11-02，詳解 6241506，付費，已解鎖查核，有幫助 7／沒幫助 0

**題目**：(二)在某次數位鑑識調查中，資安事件調查員成功從犯罪現場獲取了數位證據，調查人員現在必須保存這些數位證據以便進一步分析。為了確保數位證據的完整性，調查人員應優先考慮採取那些行動？（10 分）

**網友主解摘要與查核**：nomi 列現場照相錄影、證物標記封緘、記錄螢幕與連線、保存記憶體、製作副本並雜湊驗證、經手人簽名，方向正確，採為主解；補寫保存與運送、存取控制等事項。

**整理者補寫**：

1. **建立並維持證據監管鏈**：每件證物編號、拍照、記錄取得時間地點與狀態，每次移交都有人員簽章與時間。
2. **雜湊值固定**：取得當下對原始媒體與映像計算雜湊（建議 SHA-256，可同時保留第二種演算法），之後每次使用前後比對。
3. **只用工作複本分析**：原件以寫入保護方式處理，製作至少兩份映像，一份封存、一份分析。
4. **封緘與妥善保存**：使用防靜電袋、防拆封條；行動裝置置於法拉第袋或飛航模式防遠端抹除；存放於上鎖、溫濕度適當、限制進出且有紀錄的證物室。
5. **存取控制與紀錄**：限制可接觸證據的人員，分析工作站與儲存區設權限與日誌；分析過程逐步記錄，以便第三方重現驗證。

## 二、惡意程式逆向工程（25 分）

**題組敘述**：請回答下列問題。

### （一）無原始碼時能否逆向工程？步驟為何（15 分）

**阿摩查核**：

- [申論頁 519332](https://yamol.tw/exam/122014?info=essay.519332)：詳解 0、筆記 0、申論作答 0

**題目**：二、請回答下列問題：
(一)資安調查人員正在對從受害系統取得的某惡意程式之可執行檔進行分析，該調查人員是否可以在無原始程式碼的情況下對可執行檔進行逆向工程？如果是，其步驟為何？（15 分）

**整理者補寫**（本頁無網友詳解）：

可以。可執行檔中的機器碼可透過反組譯、反編譯與動態除錯還原程式邏輯，不需原始碼；但須在隔離環境進行，且結果是推論後的程式行為，不等於原始程式碼。步驟：

1. **準備隔離環境**：與正式網路隔離的虛擬機或實驗網路，建立快照，準備監控工具；樣本加密保存並計算雜湊。
2. **基本靜態分析**：以雜湊比對威脅情資（如 VirusTotal）、辨識檔案格式與編譯器（PE 標頭、區段、匯入表）、擷取字串，檢查是否加殼或混淆（熵值、Detect It Easy）。
3. **基本動態分析**：在沙盒執行，觀察程序、檔案、Registry、網路行為與 C2，取得 IoC。
4. **進階靜態分析**：脫殼後以 IDA Pro、Ghidra 反組譯與反編譯，分析主要函式、加密演算法、設定檔、指令集與條件分支。
5. **進階動態分析**：以 x64dbg、WinDbg 設中斷點逐步追蹤、繞過反除錯與環境檢查，傾印解密後的記憶體內容。
6. **產出**：整理行為、持久化方式、IoC、YARA 規則與清除方法，撰寫分析報告並保存紀錄。

### （二）軟體逆向工程的目的（10 分）

**阿摩查核**：

- [申論頁 519333](https://yamol.tw/exam/122014?info=essay.519333)：nomi，2024-11-02，詳解 6241511，付費，已解鎖查核，有幫助 8／沒幫助 0

**題目**：(二)說明軟體逆向工程（Software Reverse Engineering）之目的為何？（10 分）

**網友主解摘要與查核**：nomi 列分析惡意程式行為與架構、網路特徵、受感染與被修改的檔案、利用的弱點；正確但只限惡意程式情境，採為主解並補一般目的。

**整理者補寫**：逆向工程是從已編譯程式反推其結構、功能與設計的過程，目的包括：

1. **惡意程式分析**：了解感染途徑、功能、持久化與通訊方式，萃取 IoC 與偵測規則，評估影響並提出清除與防範措施，也可供鑑識歸因與作為司法證據。
2. **漏洞研究**：找出軟體或韌體缺陷、分析修補程式（patch diffing）、驗證安全性。
3. **相容性與維護**：原始碼遺失或廠商不再支援時，理解舊系統以便維護、移植或整合。
4. **智慧財產與合規檢查**：查核軟體是否侵權、含有後門或未授權元件；須注意著作權法與授權條款對逆向工程的限制。

## 三、網路攻擊（25 分）

**題組敘述**：請回答下列問題。

### （一）Session Hijacking、IP Spoofing 及兩者關係（15 分）

**阿摩查核**：

- [申論頁 519334](https://yamol.tw/exam/122014?info=essay.519334)：nomi，2024-11-02，詳解 6241686，付費，已解鎖查核，有幫助 6／沒幫助 1

**題目**：三、請回答下列問題：
(一)在網路安全攻擊中，何謂 Session Hijacking Attack？何謂 IP Spoofing？以上兩者之關係為何？（15 分）

**網友主解摘要與查核**：nomi 對兩者的定義大致正確；但「IP spoofing 可以用來在 TCP 建立連線時竊取 session ID」說法不精確。IP 偽造本身只是偽造來源位址，盲目偽造時收不到回應；能竊取 session 的是側錄、XSS 或中間人。採為主解但修正關係說明。

**整理者補寫**：

1. **Session Hijacking**：攻擊者取得或預測合法使用者已通過驗證的工作階段識別資訊，接管該連線。網路層有 TCP 劫持（猜測序號、注入封包、讓原用戶失去同步）；應用層有竊取 Web Session ID／Cookie（側錄未加密流量、XSS、惡意軟體）、Session Fixation 等。攻擊者不需密碼即可冒用身分。
2. **IP Spoofing**：偽造 IP 封包的來源位址，用以冒充受信任主機、規避以 IP 為基礎的存取控制，或在 DDoS（SYN flood、反射放大）中隱藏來源。
3. **關係**：IP 偽造是工具，Session Hijacking 是目的。經典的 TCP 劫持中，攻擊者先讓受信任主機無法回應（如 SYN flood），再偽造其 IP 並預測序號，注入封包接管或建立連線（如 Mitnick 攻擊）；在同一網段可結合 ARP 偽造做中間人，看到雙方封包後劫持更容易。單靠 IP 偽造看不到回應，故不必然能完成劫持；反過來，竊取 Cookie 的應用層劫持也不需要偽造 IP。
4. **防範**：全程 TLS、Cookie 設 Secure／HttpOnly／SameSite、登入後重新產生 Session ID、逾時與綁定檢查；邊界設入出口過濾（BCP 38）、隨機初始序號、不以 IP 作為唯一信任依據。

### （二）何謂 Sniffing 及其目的（10 分）

**阿摩查核**：

- [申論頁 519335](https://yamol.tw/exam/122014?info=essay.519335)：nomi，2024-11-02，詳解 6241690，付費，已解鎖查核，有幫助 4／沒幫助 0

**題目**：(二)說明什麼是 sniffing？其目的為何？（10 分）

**網友主解摘要與查核**：nomi 定義與目的正確但簡略（引資安人科技網），採為主解並補充方式與防範。

**整理者補寫**：Sniffing（網路監聽）是擷取並解析流經網路介面之封包的行為，網卡設為混雜模式即可收取同一碰撞域的流量；在交換式網路需搭配 ARP 偽造、MAC flooding 或連接埠鏡像，無線網路可被動收取空中訊號。

目的分兩面：攻擊者用來竊取明文帳密（Telnet、FTP、HTTP、POP3）、Cookie、郵件與檔案，蒐集網路拓樸作為後續攻擊；管理者與鑑識人員則以 Wireshark、tcpdump 合法側錄，用於故障排除、效能分析、入侵偵測與事件鑑識。防範：全面加密傳輸（TLS、SSH、VPN、WPA3）、交換器啟用 Port Security 與 DAI、偵測混雜模式網卡與異常 ARP。

### （一）Phishing、Vishing、Smishing 的差異（15 分）

**阿摩查核**：

- [申論頁 519336](https://yamol.tw/exam/122014?info=essay.519336)：Jay Chuang，2025-06-09，詳解 6470311，標示由 ChatGPT 產生，付費，已解鎖查核，有幫助 2／沒幫助 0

**題目**：(一)攻擊者不斷尋找利用傳送訊息進行破壞的新威脅。請說明 phishing、 vishing 與 smishing 之差異。（15 分）

**網友主解摘要與查核**：Jay Chuang（標示 ChatGPT）以媒介、互動方式、常見手法比較三者，並附防範建議，正確，採為主解。

**整理者補寫**：三者都是冒充可信對象、製造急迫感，騙取帳密、個資、金錢或誘導安裝惡意程式的社交工程，差異在媒介：

| 類型 | 媒介 | 常見手法 | 防範重點 |
|---|---|---|---|
| Phishing | 電子郵件、假網站（含魚叉式、鯨釣） | 假冒銀行、主管、系統通知，附偽造登入連結或惡意附件 | 郵件過濾、SPF／DKIM／DMARC、檢查網址、MFA |
| Vishing | 電話、語音、網路電話（可偽造來電顯示、AI 合成語音） | 假冒客服、檢警、主管要求轉帳或提供驗證碼 | 掛斷後以官方電話回撥查證、不提供 OTP |
| Smishing | 手機簡訊、即時通訊 | 包裹、罰單、帳戶異常通知夾帶短網址 | 不點簡訊連結、從官方 App 或網站查詢、行動防護軟體 |

### （二）何謂 S/MIME（10 分）

**阿摩查核**：

- [申論頁 519337](https://yamol.tw/exam/122014?info=essay.519337)：nomi，2024-11-02，詳解 6241693，付費，已解鎖查核，有幫助 5／沒幫助 1

**題目**：(二)簡述何謂 S/MIME（Secure/Multipurpose Internet Mail Extensions）？（10 分）

**網友主解摘要與查核**：nomi 引 Microsoft 支援說明，指出 S/MIME 提供加密與數位簽章，正確但未說明運作，採為主解並補寫。

**整理者補寫**：S/MIME 是以公開金鑰基礎建設（X.509 憑證）保護 MIME 電子郵件的標準（現行版本 RFC 8551）。寄件者以私鑰對郵件雜湊簽章，提供來源鑑別、完整性與不可否認性；以隨機對稱金鑰加密郵件本文，再用收件者憑證中的公鑰加密該對稱金鑰（數位信封），提供機密性。收件者以自己的私鑰解密、以寄件者憑證驗證簽章。它屬於端對端保護，與 TLS 只保護傳輸過程不同；但收發雙方都需要憑證並交換公鑰，郵件標頭（主旨等）通常不加密，憑證過期或撤銷也要管理。
