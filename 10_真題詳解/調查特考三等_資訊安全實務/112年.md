# 112 年調查特考三等：資訊安全實務

查核日：2026-10-11。題文見[試題轉錄](../../11_公職特考與高考二級_資安科目_試題/調查特考三等_資訊安全實務_111-115.md#112年)，官方原卷見[考選部 PDF](https://wwwq.moex.gov.tw/exam/wHandExamQandA_File.ashx?t=Q&code=112130&c=414&s=1007&q=1)。阿摩有兩份相同試卷（116094、120694），兩份的詳解一併比較，每題只選一份主解；非官方標準答案。

## 一、數位證據保全標準作業程序：電腦設備或儲存媒體蒐集（25 分）

**阿摩查核**：

- [申論頁 495788](https://yamol.tw/exam/116094?info=essay.495788)：Aaron Lim，2023-08-24，詳解 5918653，付費，已解鎖查核，有幫助 3／沒幫助 1
- [申論頁 514111](https://yamol.tw/exam/120694?info=essay.514111)：nomi，2024-07-25，詳解 6176927，付費，已解鎖查核，有幫助 10／沒幫助 0；申論作答 1334（吳海嫄本山，2026-01-28，245 字，阿摩 AI 評分 67）

**題目**：一、請條列並說明「數位證據保全標準作業程序」中，進行「電腦設備或儲存媒體蒐集」之作法。（25 分）

**網友主解摘要與查核**：116094 的 Aaron Lim與 120694 的 nomi 都逐字引用行政院《政府機關（構）資安事件數位證據保全標準作業程序》六、（二）第 1 至 4 點，內容一致；nomi 版有用幫助 10 則，選為主解。原文正確，但純引條文，未說明前置準備與記錄要求，以下整理成作答格式。申論作答 1334（吳海嫄本山）以封緘、拆卸錄影、不中斷服務時現場轉錄、填寫工作表四點作答，方向正確但省略外接媒體與拍照步驟，未選。

**整理者補寫**（依該作業程序；條次以作業程序本身為準）：

1. **可關機時，以封緘完整設備為原則**：機關原則上封緘整部電腦，交上級機關或鑑識單位後續處理；確有拆卸必要時，記錄人員全程錄影拆卸與取出儲存媒體過程，媒體封緘後視需要送上級機關或鑑識單位。無上級機關者，由該機關行使上級機關職權。
2. **外接儲存媒體**：可關機且有外接式媒體時，同樣封緘並視需要送交，拆卸取出全程錄影；以拍照代替時，須拍攝拆卸前（含線材連接）、拆卸後（含線材已拔除）與取出時三個階段。
3. **伺服主機不能中斷服務**：不得任意關機，應在上級機關或鑑識單位監督下以嚴謹方式轉錄資料（線上採集），並記錄所用工具與步驟。
4. **記錄與工作表**：拍攝媒體的廠牌、型號、序號、容量，將蒐集結果填入「數位證據蒐集工作表（電腦設備）」或「（儲存媒體）」。

作答時可再補共通要求：蒐集前先依同一程序保存揮發性資料（記憶體、網路連線、執行程序等），封緘須簽名註記日期，移交全程登載於證據監管紀錄，後續分析對媒體製作映像並以雜湊驗證完整性。

## 二、三項 IDPS 偵測技術的五面向比較（25 分）

**阿摩查核**：

- [申論頁 495789](https://yamol.tw/exam/116094?info=essay.495789)：Aaron Lim，2023-08-24，詳解 5918708，付費，已解鎖查核，有幫助 2／沒幫助 0
- [申論頁 514112](https://yamol.tw/exam/120694?info=essay.514112)：一起撐住一起上榜，2025-11-16，詳解 7103210，標示由 ChatGPT 產生，付費，已解鎖查核，有幫助 2／沒幫助 0

**題目**：二、請條列說明三項 IDPS（Intrusion Detection and Prevention System）偵測技術，並就精準度、已知攻擊、未知攻擊、計算能力與策略調整方式等五個面向做比較。（25 分）

**網友主解摘要與查核**：兩份詳解都列簽章式、異常式、狀態式三項。Aaron Lim 版把「狀態式」寫成「需要定期更新狀態轉移規則」，計算能力標為中等；一起撐住一起上榜版（ChatGPT）稱為「規則／狀態偵測」，混入 Policy-based。依 NIST SP 800-94，三種方法是 Signature-based、Anomaly-based、Stateful protocol analysis。選 Aaron Lim 版為主解，但修正比較表：狀態協定分析需追蹤每個連線狀態，是三者中最耗資源的，不是中等。

**整理者補寫**：

1. **簽章式偵測**：比對已知攻擊特徵（字串、封包樣式、雜湊），實作簡單。
2. **異常式偵測**：先建立網路、主機或使用者的正常行為基準，偏離程度超過門檻即告警，可用統計或機器學習。
3. **狀態式協定分析**：依廠商公告的協定規格建立「正常協定行為」模型，追蹤連線與應用層狀態，找出不符合規格的指令順序、參數長度或異常狀態轉移。

| 面向 | 簽章式 | 異常式 | 狀態式協定分析 |
|---|---|---|---|
| 精準度 | 已知攻擊誤報低；稍有變形即漏報 | 誤報率高，基準設定影響大 | 對協定違規判斷精確，但規格不明或實作差異會誤判 |
| 已知攻擊 | 最有效 | 可偵測但不一定能指出攻擊名稱 | 能偵測利用協定異常的已知攻擊 |
| 未知攻擊 | 幾乎無法偵測 | 較能偵測零時差與內部異常 | 可偵測違反協定的新型攻擊，對「符合協定」的攻擊無效 |
| 計算能力 | 最低 | 中到高（建模與即時比對） | 最高，需保存並追蹤大量連線狀態 |
| 策略調整 | 持續更新簽章庫、可自訂規則 | 需學習期，環境改變要重建基準、調整門檻 | 協定更新或新協定需修改模型，難以涵蓋私有協定 |

實務上 IDPS 多採混合式，以簽章式處理已知攻擊、異常與協定分析補足未知攻擊。

## 三、零信任核心機制與六項原則（30 分）

**阿摩查核**：

- [申論頁 495790](https://yamol.tw/exam/116094?info=essay.495790)：Aaron Lim，2023-08-26，詳解 5919428，付費，已解鎖查核，有幫助 4／沒幫助 0
- [申論頁 514113](https://yamol.tw/exam/120694?info=essay.514113)：nomi，2025-06-10，詳解 6470451，付費，已解鎖查核，有幫助 6／沒幫助 0

**題目**：三、請條列說明零信任（Zero Trust）的核心機制與六項組織應考量的零信任原則。（30 分）

**網友主解摘要與查核**：Aaron Lim 版引用政府零信任架構的三大核心機制（身分鑑別、設備鑑別、信任推斷）與 NIST SP 800-207 第 2.2 節「零信任觀點」六項（企業私有網路不視為信任區等），作答方向符合題意，選為主解（120694 另有一份 ChatGPT 詳解，未選）。但題目說的「六項原則」可能是 NIST 列出的零信任基本信條（tenets，共七項）中的六項，或 2.2 節的六項網路觀點；為避免失分，以下兩者都說明並寫明出處。

**整理者補寫**：

1. **零信任概念**：不因位於內網或曾通過驗證而預設信任，每次存取資源都依身分、裝置、情境動態驗證與授權，並以最小權限與持續監控為原則。
2. **核心機制**（NIST 邏輯元件與我國政府架構）：
   - **政策決策點／執行點（PDP／PEP）**：政策引擎依政策與信任演算法決定是否允許，政策管理員下達，執行點在資源前把關；所有存取都經過此路徑。
   - **身分鑑別**：多因子、抗釣魚鑑別（如 FIDO），並傳遞鑑別聲明。
   - **設備鑑別**：確認裝置身分與健康狀態（是否受管、修補、EDR 運作、組態合規）。
   - **信任推斷**：綜合使用者行為、存取時間地點、裝置狀態與威脅情資，動態計算信任分數，結果決定准駁或要求再驗證。
   - **持續診斷與監控**：日誌、威脅情資、CDM 系統回饋給政策引擎。
3. **組織應考量的原則**（NIST SP 800-207 第 2.1 節信條）：所有資料來源與運算服務都視為資源；不論網路位置，所有通訊都必須保護；每次存取個別工作階段授權；以動態政策（身分、應用、裝置與環境屬性）決定存取；監控並量測所有資產的完整性與安全狀態；鑑別與授權是動態並嚴格執行的；盡可能蒐集資產、網路與通訊狀態資訊來改善安全態勢。答「六項」時擇其六並說明即可。
4. **零信任觀點**（同文件第 2.2 節六項）：企業私有網路不是隱含信任區；網路上的裝置不一定為企業所有或可設定；沒有資源是天生可信的；企業資源不一定都在企業自有基礎設施上；遠端使用者不能信任其所在的區域網路；在企業與非企業基礎設施間移動的資產與工作流程，應維持一致的安全政策與狀態。

## 四、未取模的 Diffie-Hellman 破解（20 分）

**阿摩查核**：

- [申論頁 495791](https://yamol.tw/exam/116094?info=essay.495791)：Aaron Lim，2023-11-08，詳解 5961811，付費，已解鎖查核，有幫助 2／沒幫助 0
- [申論頁 514114](https://yamol.tw/exam/120694?info=essay.514114)：詳解 0、筆記 0、申論作答 0

**題目**：四、以下是張三和李四以 Diffie-Hellman key exchange 之技術為基礎欲產生共同密鑰，但未做取模運算（Modulus），所以也沒有選定 Diffie-Hellman key exchange 模數運算的質數，他們所選用的公開基礎參數（底數）g 為 3。請從他們交換的參數破解出張三的秘密參數 XA、李四的秘密參數 XB 以及他們產生的共同密鑰 Key。（需有推演計算的過程才給分）（20 分）張三：選定秘密參數 XA，後計算出公開參數 YA = 27 傳給李四。李四：選定秘密參數 XB，後計算出公開參數 YB = 243 傳給張三。張三、李四：各自計算出二人的共同密鑰 Key。

**網友主解摘要與查核**：Aaron Lim 版求得 XA = 3、XB = 5、Key = 14348907，結果正確，選為主解；但文中把 YA、YB 對調，且出現「2433」「275」等把指數寫成數字的排版錯誤（應為 243³、27⁵），以下重寫計算。

**整理者補寫**：

1. Diffie-Hellman 原本是 YA = g^XA mod p、YB = g^XB mod p，共同金鑰 K = YB^XA mod p = YA^XB mod p。安全性來自離散對數難解。本題沒有取模，Y = g^X 在整數上直接成立，只要取對數就能求出秘密參數。
2. 張三：YA = 3^XA = 27 = 3³，所以 **XA = 3**。
3. 李四：YB = 3^XB = 243 = 3⁵，所以 **XB = 5**。
4. 共同密鑰：張三算 K = YB^XA = 243³ = 14,348,907；李四算 K = YA^XB = 27⁵ = 14,348,907；兩者相同，也等於 3^(3×5) = 3¹⁵。**Key = 14348907**。
5. 說明：未取模時任何人都能以 log₃ 由公開參數反推秘密，金鑰交換毫無安全性；實務必須選用夠大的質數 p（或橢圓曲線群），並搭配身分鑑別防止中間人攻擊。
