## 一、雜湊函數與生日攻擊（25 分）

**題組敘述**：請回答下列有關雜湊函數與生日攻擊之問題。

### （一）雜湊函數的應用與理想特性（10 分）

**阿摩查核**：

- [申論頁 576804](https://yamol.tw/exam/140786?info=essay.576804)：申論作答 107306（milktea810182，2026-09-23，291 字，阿摩 AI 評分 74）

**題目**：(一)雜湊函數（Cryptographic Hash Functions）有那些應用？一個理想的 Cryptographic Hash Function 必須具備那些關鍵特性？說明其理由並舉例。（10 分）

**網友作答查核**：本頁無詳解；申論作答 107306（milktea810182，阿摩 AI 評分 74）列應用與單向性、抗碰撞、抗第二原像、雪崩效應等特性，大致正確，但「固定長度、高效率」是一般雜湊函數性質，不是密碼學安全特性的核心，且未說明理由與例子。以下補寫。

**整理者補寫**：

1. **應用**：檔案與訊息完整性驗證（下載檔附 SHA-256 值、數位鑑識映像雜湊）；數位簽章前先對訊息雜湊再簽；訊息鑑別碼（HMAC）；密碼儲存（加鹽並使用 bcrypt、Argon2 等慢雜湊）；區塊鏈與 Merkle tree；惡意程式樣本識別與威脅情資 IoC；虛擬隨機數與金鑰推導（HKDF）。
2. **理想特性與理由**：
   - **抗原像（單向性）**：給定雜湊值 h，難以找到 m 使 H(m)=h。理由：否則可由儲存的密碼雜湊反推密碼。例：資料庫外洩時攻擊者只得到雜湊。
   - **抗第二原像**：給定 m1，難以找到 m2≠m1 且 H(m2)=H(m1)。理由：否則可把已簽章或已記錄雜湊的檔案換成惡意檔而不被發現。例：軟體發布的雜湊值保護。
   - **抗碰撞**：難以找到任意一對 m1≠m2 且 H(m1)=H(m2)。理由：否則攻擊者可準備兩份內容不同但雜湊相同的文件，讓對方簽一份、再換成另一份。例：MD5、SHA-1 已能產生碰撞，被用來偽造憑證，因此已淘汰。
   - **雪崩效應與決定性**：輸入改一位元，輸出約半數位元改變；同一輸入永遠得到同一輸出，才可用於比對。
   - **輸出長度足夠**：抗碰撞強度約為輸出長度的一半（生日界限），故建議 SHA-256 以上。

### （二）生日攻擊及其對網路應用的威脅（15 分）

**阿摩查核**：

- [申論頁 576805](https://yamol.tw/exam/140786?info=essay.576805)：詳解 0、筆記 0、申論作答 0

**題目**：(二)詳細說明什麼是生日攻擊（Birthday Attack）？Birthday Attack 對於網路資訊應用帶來什麼資安威脅？請舉例說明之。（15 分）

**整理者補寫**（本頁無網友詳解）：

1. **原理**：生日悖論指一群人中只要約 23 人，有兩人同一天生日的機率就超過 50%。推廣到雜湊：輸出 n 位元共有 2ⁿ 種值，若要找「任一對」碰撞，只需約 √(2ⁿ) = 2^(n/2) 次嘗試即有約 50% 機率成功，遠少於找特定原像所需的 2ⁿ 次。公式近似 P ≈ 1 − e^(−k²/2N)。
2. **攻擊方式**：攻擊者準備兩組文件，一組無害（如正常合約）、一組有利於自己（如改金額），各產生大量語意不變的變體（空白、同義詞），找出一對雜湊相同者；讓受害者對無害版簽章，再把簽章套在惡意版本上，驗證仍會通過。
3. **對網路資訊應用的威脅**：
   - 數位簽章與憑證偽造：2008 年研究者利用 MD5 碰撞偽造可被瀏覽器信任的 CA 憑證；Flame 惡意程式利用 MD5 碰撞偽造 Microsoft 程式碼簽章。
   - 2017 年 SHAttered 產生兩份 SHA-1 雜湊相同的 PDF，影響使用 SHA-1 的簽章、版本控制（Git）與文件完整性驗證。
   - 分組長度短的加密（如 64 位元區塊的 3DES、Blowfish）在大量資料下出現區塊碰撞，可還原 HTTPS Cookie（Sweet32 攻擊）。
   - 隨機數或識別碼過短（Session ID、nonce）時容易重複，造成重放或工作階段混淆。
4. **防範**：使用 SHA-256、SHA-3 等輸出長度足夠的雜湊，停用 MD5、SHA-1；簽章前加入隨機值（隨機化雜湊、憑證序號隨機化）；採 128 位元分組的 AES；Session ID 與 nonce 使用足夠長度的安全亂數。

## 二、網路安全偵察與協定攻擊（25 分）

**題組敘述**：請回答下列有關網路安全偵察以及協定攻擊之問題。

### （一）網路安全偵察與主動、被動偵察的差異（10 分）

**阿摩查核**：

- [申論頁 576806](https://yamol.tw/exam/140786?info=essay.576806)：詳解 0、筆記 0、申論作答 0

**題目**：(一)何謂網路安全偵察（Cybersecurity Reconnaissance）？被動偵查與主動偵查之差異為何？請詳細說明並舉例。（10 分）

**整理者補寫**（本頁無網友詳解）：網路安全偵察是攻擊（或授權測試）前蒐集目標組織、人員、網路與系統資訊，以找出可利用弱點與攻擊路徑的階段，對應 Cyber Kill Chain 第一步與 MITRE ATT&CK 的 Reconnaissance 戰術。

| 面向 | 被動偵察 | 主動偵察 |
|---|---|---|
| 方式 | 不直接與目標系統互動，蒐集公開資訊（OSINT） | 直接送封包或請求到目標系統 |
| 例子 | WHOIS、DNS 公開紀錄、搜尋引擎（Google Hacking）、Shodan、社群網站與人資網頁、憑證透明度紀錄、外洩資料庫 | Ping sweep、Nmap 埠掃描與服務版本偵測、弱點掃描、DNS 區域傳送測試、網頁目錄爆破、社交工程電話 |
| 被發現的可能 | 極低，目標難以察覺 | 高，可能觸發 IDS 或留下日誌 |
| 資訊精確度 | 可能過時或不完整 | 即時、精確 |
| 法律風險 | 一般較低 | 未經授權掃描可能違法 |

防禦：減少公開資訊暴露、隱藏服務版本、監控掃描行為與告警、蜜罐誘捕。

### （二）網路協定攻擊的常見方法與防禦（15 分）

**阿摩查核**：

- [申論頁 576807](https://yamol.tw/exam/140786?info=essay.576807)：詳解 0、筆記 0、申論作答 0

**題目**：(二)何謂網路協定攻擊（Network Protocol Attack）？網路協定攻擊有那些常見的攻擊方法？舉例說明有那些防禦策略？（15 分）

**整理者補寫**（本頁無網友詳解）：網路協定攻擊是利用通訊協定設計上的缺陷（多數早期協定缺乏鑑別與完整性保護）或實作漏洞，以偽造、竄改、重送、耗盡資源等方式攻擊。

| 層級 | 常見攻擊 | 防禦策略 |
|---|---|---|
| 資料鏈結層 | ARP 偽造（中間人）、MAC flooding、VLAN hopping、DHCP 偽冒與耗盡 | 動態 ARP 檢查（DAI）、DHCP Snooping、Port Security、802.1X、停用未用埠與 DTP |
| 網路層 | IP 偽造、ICMP 重導與 Smurf、BGP 劫持、路由協定偽造 | 入出口過濾（BCP 38）、uRPF、RPKI 與 BGP 前綴過濾、路由協定鑑別 |
| 傳輸層 | TCP SYN flood、TCP 工作階段劫持與 RST 注入、UDP 反射放大 | SYN cookies、連線速率限制、隨機初始序號、DDoS 清洗服務、關閉不需要的 UDP 服務 |
| 應用層 | DNS 快取汙染、DNS 放大、HTTP 慢速攻擊（Slowloris）、SSL/TLS 降級（POODLE）、SMTP 偽冒 | DNSSEC、限制遞迴查詢、WAF 與逾時設定、停用舊版 SSL／TLS、SPF／DKIM／DMARC |

整體上以加密與鑑別（TLS、IPsec、SSH）取代明文協定、網段隔離、IDS／IPS 監控與修補設備韌體。

## 三、Evil Twin 與 WPA（25 分）

**題組敘述**：使用公共 Wi-Fi 傳送機敏資料會帶來資安風險，例如：遭受邪惡孿生（Evil Twin）攻擊。

### （一）Evil Twin 攻擊與威脅（10 分）

**阿摩查核**：

- [申論頁 576808](https://yamol.tw/exam/140786?info=essay.576808)：詳解 0、筆記 0、申論作答 0

**題目**：(一)何謂 Evil Twin 攻擊？Evil Twin 攻擊有那些資安威脅？舉例說明之。（10 分）

**整理者補寫**（本頁無網友詳解）：Evil Twin 是攻擊者架設與合法熱點相同 SSID（甚至相同 BSSID）的偽冒無線基地台，常以較強訊號或發送解除認證（deauthentication）封包把使用者從真熱點踢下，誘使裝置自動連到假熱點。威脅：

1. **竊聽與中間人**：所有流量經攻擊者，可側錄明文帳密、Cookie，竄改網頁或注入惡意程式。
2. **假入口網頁釣魚**：要求重新輸入 Wi-Fi 密碼或以社群帳號、信用卡登入，例如咖啡店熱點彈出「重新驗證」頁面。
3. **DNS 劫持與 SSL 剝離**：把使用者導向假的網銀或企業登入頁，或降級成 HTTP。
4. **散布惡意程式、取得企業 PSK**：誘騙下載偽冒更新；在企業環境騙取 WPA2-Enterprise 憑證（如攻擊未驗證伺服器憑證的 PEAP 設定）。

防範：避免在公共 Wi-Fi 處理機敏資料或使用 VPN；只連 HTTPS 並留意憑證警告；關閉自動連線；企業使用 802.1X 並強制驗證 RADIUS 伺服器憑證，部署 WIPS 偵測惡意 AP；啟用 802.11w 管理框架保護抵抗 deauth。

### （二）WPA 及其實現的三項安全特性（15 分）

**阿摩查核**：

- [申論頁 576809](https://yamol.tw/exam/140786?info=essay.576809)：詳解 0、筆記 0、申論作答 0

**題目**：(二)何謂保護無線網路的安全協定（Wi-Fi Protected Access, WPA）？WPA 及其相關的標準實現了那三項安全特性，以解決使用網路遭遇到的安全問題？詳細說明之。（15 分）

**整理者補寫**（本頁無網友詳解）：WPA（Wi-Fi Protected Access）是 Wi-Fi 聯盟為取代有嚴重缺陷的 WEP 所制定的無線安全認證，WPA 為過渡版（TKIP）、WPA2 實作 IEEE 802.11i（CCMP／AES）、WPA3 再強化（SAE、GCMP、管理框架保護）。三項安全特性：

1. **身分鑑別與存取控制**：個人模式以預先共用金鑰（PSK），WPA3 改用 SAE（同步對等鑑別，抵抗離線字典攻擊並提供前向保密）；企業模式以 802.1X／EAP 透過 RADIUS 伺服器鑑別個別使用者或裝置。四向交握確認雙方都持有成對主金鑰，並推導每個工作階段的暫時金鑰。
2. **機密性（資料加密）**：WPA 以 TKIP 每封包變換金鑰改善 WEP 的 RC4 金鑰重用；WPA2 使用 AES-CCMP；WPA3 企業 192 位元模式使用 GCMP-256。每位使用者與每個工作階段金鑰不同，他人無法解讀。
3. **完整性與防重放**：WPA 以 Michael MIC、WPA2／WPA3 以 CCMP（CBC-MAC）或 GCMP 的訊息完整性檢查，取代 WEP 可被竄改的 CRC-32；封包序號（PN）防止重放；WPA3 強制管理框架保護（PMF）防止偽造解除認證。

公共場所可用 Wi-Fi Enhanced Open（OWE），即使無密碼也提供個別加密。

## 四、資安事件通報應變與 ISO/IEC 27035（25 分）

**題組敘述**：資安事件之處理與應變，需要遵循國家相關的法規，以及國際標準。

### （一）通報應變的法律依據、事件分級與通報內容（10 分）

**阿摩查核**：

- [申論頁 576810](https://yamol.tw/exam/140786?info=essay.576810)：詳解 0、筆記 0、申論作答 0

**題目**：(一)有關資安事件之通報與應變，我國是依據那部法律，訂定什麼辦法加以規範？並說明其對於資安事件如何分級，以及通報內容應包括之項目。（10 分）

**整理者補寫**（本頁無網友詳解）：

1. **法律與辦法**：依《資通安全管理法》（114 年修正、114 年 12 月 1 日施行）授權，訂定《資通安全事件通報應變及演練辦法》（原名《資通安全事件通報及應變辦法》，現行版本於 115 年 1 月修正）。
2. **事件分級**（第 2 條，分四級，第四級最嚴重）：依資訊洩漏或竄改的嚴重程度、是否涉及核心業務、關鍵基礎設施、一般公務機密或國家機密，以及系統能否在可容忍中斷時間內恢復判斷。例如非核心業務資訊或系統輕微洩漏、竄改、中斷但可如期恢復為第一級；涉及國家機密洩漏或竄改、關鍵基礎設施核心系統無法如期恢復為第四級。處理時限依等級區分（見下）。
3. **通報內容**（第 3 條七項）：發生機關、發生或知悉時間、狀況之描述、等級之評估、因應事件所採取之措施、外部支援需求評估、其他相關事項。
4. **時限補充**：公務機關知悉後一小時內通報（第 6 條），等級變更應續報；第一、二級於知悉後 72 小時內、第三、四級於 36 小時內完成損害控制或復原，並於完成後一個月內送交調查、處理及改善報告（第 8 條）。

### （二）ISO/IEC 27035 事件管理生命週期的目的與優勢（15 分）

**阿摩查核**：

- [申論頁 576811](https://yamol.tw/exam/140786?info=essay.576811)：詳解 0、筆記 0、申論作答 0

**題目**：(二) ISO/IEC 27035 事件管理生命週期（Incident Management Lifecycle）的目的為何？透過遵循事件管理生命週期會有那些優勢？（15 分）

**整理者補寫**（本頁無網友詳解）：

1. **生命週期**（ISO/IEC 27035-1:2023）：規劃與準備（政策、應變團隊、程序、工具、訓練）→ 偵測與通報（監控、通報管道）→ 評估與決策（判斷是否為事件、分類分級）→ 回應（圍堵、根除、復原、鑑識、溝通）→ 學習經驗（檢討、改善控制措施與程序）。
2. **目的**：以結構化、可重複的方式偵測、通報、評估、回應資訊安全事件，降低事件對業務的衝擊，蒐集並保全證據，並把經驗回饋到風險管理與 ISMS，持續改善。
3. **優勢**：
   - 及早偵測與一致的分級決策，避免慌亂與遺漏。
   - 明確角色、權責與溝通管道，縮短回應時間，減少損失與停機。
   - 依程序保全證據，支援鑑識與法律行動。
   - 符合法規與通報要求、提升利害關係人信任，與 ISO/IEC 27001 控制措施（A.5.24 至 A.5.28）整合。
   - 經驗學習使控制措施、偵測規則與訓練持續改善，降低再發生機率；可與國內通報辦法、NIST SP 800-61 對照運用。
