## 一、資料儲存的資安需求與可用技術（25 分）

**阿摩查核**：

- [申論頁 543615](https://yamol.tw/exam/127676?info=essay.543615)：蝦皮:警察法規白話解題，2025-06-21，詳解 6497534，標示由 GoogleAI 產生，付費，已解鎖查核，有幫助 4／沒幫助 0

**題目**：一、請說明資料在儲存上需要滿足那些資安需求以及滿足這些需求的可用技術。（25 分）

**網友主解摘要與查核**：依機密性、完整性、可用性、可稽核性等面向列加密、存取控制、遮罩、雜湊、簽章、備份、RAID、日誌等技術，架構正確，選為主解；但把 MD5 列為完整性雜湊、RSA 列為儲存加密演算法不妥（MD5 已不安全；大量資料加密用對稱式，RSA 只用於保護金鑰），且漏了金鑰管理與安全刪除，以下修正。

**整理者補寫**：

| 需求 | 說明 | 可用技術 |
|---|---|---|
| 機密性 | 只有授權者能讀取靜態資料 | 全磁碟或檔案加密（AES-256、BitLocker、LUKS）、資料庫透明加密（TDE）與欄位加密、存取控制（RBAC／ABAC、最小權限）、遮罩、代碼化、去識別化 |
| 完整性 | 資料不被未授權或意外竄改 | SHA-256 以上雜湊與 HMAC、數位簽章、檔案完整性監控、WORM 不可變儲存、資料庫約束與交易紀錄、版本控制 |
| 可用性 | 需要時可取用，可從故障與攻擊中恢復 | RAID、複寫與叢集、3-2-1 備份（含離線或不可變副本）、異地備援、定期還原測試、勒索防護 |
| 可稽核性與不可否認性 | 能追蹤誰在何時做了什麼 | 稽核日誌、時間同步、日誌防竄改與集中保存（SIEM）、數位簽章 |
| 金鑰管理 | 加密的安全取決於金鑰 | KMS、HSM、金鑰分持、輪替、與資料分開保存 |
| 資料生命週期與法遵 | 依保存期限保存、到期安全銷毀、符合個資法 | 資料分類分級、保存政策、安全抹除或加密銷毀（crypto-erase）、實體媒體銷毀（依 NIST SP 800-88） |

## 二、封包過濾、狀態檢視與應用代理閘道防火牆（25 分）

**阿摩查核**：

- [申論頁 543616](https://yamol.tw/exam/127676?info=essay.543616)：蝦皮:警察法規白話解題，2025-06-21，詳解 6497536，標示由 GoogleAI 產生，付費，已解鎖查核，有幫助 2／沒幫助 0

**題目**：二、請說明封包過濾防火牆、狀態檢視防火牆及應用代理閘道防火牆其具體的功能及差異。（25 分）

**網友主解摘要與查核**：三種防火牆的檢查層級、優缺點與比較表正確，選為主解；但比較表稱狀態檢視「設定複雜度低、效能較佳」與封包過濾相比不精確，且應用代理的「連線狀態追蹤」說法可再明確。以下整理。

**整理者補寫**：

| 項目 | 封包過濾 | 狀態檢視 | 應用代理閘道 |
|---|---|---|---|
| 運作層級 | 網路層、傳輸層 | 網路層、傳輸層，加上連線狀態表 | 應用層（代理伺服器） |
| 判斷依據 | 每個封包標頭的來源／目的 IP、埠號、協定、旗標，逐一比對 ACL | 除標頭外追蹤 TCP 三向交握與連線狀態，回應封包須屬於既有連線才放行 | 終止用戶端連線，以代理身分另建連線到伺服器，解析應用協定內容（URL、指令、檔案類型） |
| 優點 | 簡單、快速、成本低，常內建於路由器 | 能阻擋不屬於既有連線的偽造封包，規則較少（回程自動放行），效能與安全兼顧 | 可做內容過濾、使用者鑑別、記錄完整應用層日誌，隱藏內部主機 |
| 缺點 | 無狀態，難防偽造與分段攻擊，須手動開放回程高埠 | 不檢查應用層內容，狀態表可能被耗盡（SYN flood） | 每種協定需專屬代理，效能較低、延遲較高，加密流量需解密 |
| 典型用途 | 邊界路由器初步過濾 | 企業防火牆基本功能 | Web Proxy、郵件閘道、高安全區域 |

現代次世代防火牆（NGFW）整合狀態檢視、應用辨識、IPS 與 TLS 檢查。

## 三、內部無線網路的五項安全措施（25 分）

**阿摩查核**：

- [申論頁 543617](https://yamol.tw/exam/127676?info=essay.543617)：蝦皮:警察法規白話解題，2025-06-21，詳解 6497538，標示由 GoogleAI 產生，付費，已解鎖查核，有幫助 4／沒幫助 0

**題目**：三、你被指派設定單位內部的無線網路，請列出五項你會採取的安全措施來確保無線網路使用上的安全，並說明其目的。（25 分）

**網友主解摘要與查核**：列 WPA3／WPA2、更改預設 SSID 與密碼、MAC 位址過濾、更新韌體、訪客網路隔離，並建議關閉 WPS，方向正確，選為主解。但 MAC 過濾易被偽造，不宜作為主要措施；「單位內部」更適合採 802.1X 企業模式，以下調整為較適合機關的五項。

**整理者補寫**：

1. **WPA3-Enterprise（或 WPA2-Enterprise）＋802.1X**：每人或每台裝置以 RADIUS 個別鑑別（EAP-TLS 憑證最佳），避免共用密碼外流；人員離職即可停用。目的：存取控制與可歸責。
2. **強加密與管理框架保護**：使用 AES-CCMP／GCMP，停用 WEP、TKIP 與 WPS，啟用 802.11w（PMF）。目的：防竊聽、竄改與解除認證攻擊。
3. **網段隔離**：員工、訪客、IoT 分屬不同 SSID 與 VLAN，訪客網路只能上網、啟用用戶端隔離；無線網路經防火牆才能進入內部系統。目的：限制入侵擴散。
4. **設備安全管理**：變更 AP 與控制器預設管理密碼、管理介面只允許有線管理網段、更新韌體、關閉不必要服務、調整發射功率避免訊號外洩。目的：防止設備遭入侵。
5. **監控與偵測**：部署無線入侵防禦系統（WIPS）偵測惡意 AP、Evil Twin 與私接基地台，連線日誌送 SIEM，定期無線安全檢測。目的：及早發現異常並保存紀錄。

**題目**：四、請就資安事件處理過程中對於資料保存、事件通報、損害控制及調查、處理與改善報告的執行要項做一具體說明。（25 分）

**網友主解摘要與查核**：從證據保全、通報、圍堵與調查、改善報告說明，方向正確，選為主解；但通報部分以 GDPR 為例，未依我國法規寫出時限與內容。以下以考試時《資通安全事件通報及應變辦法》與數位證據保全作業程序補寫。

**整理者補寫**：

1. **資料保存**：發現事件即保全相關資料：系統、應用、資安設備與網路設備日誌、記憶體與磁碟映像、封包；先取揮發性資料再處理磁碟，以寫入保護與雜湊值確保完整，填寫證據監管紀錄；不可任意關機、重灌或刪除；依法規與機關規定的期限保存。
2. **事件通報**：公務機關知悉後**一小時內**依主管機關指定方式通報（特定非公務機關向中央目的事業主管機關通報），內容含發生機關、發生或知悉時間、狀況描述、等級評估、已採取措施、外部支援需求、其他事項；等級變更或有新資訊時續報；涉及個資外洩另依個資法通知當事人，涉及犯罪向檢警報案。
3. **損害控制及調查**：啟動應變小組，隔離受害主機、封鎖惡意連線、停用遭竊帳號，防止擴散；第一、二級事件於知悉後 **72 小時**內、第三、四級於 **36 小時**內完成損害控制或復原，並回報主管機關；同時鑑識調查入侵途徑、影響範圍與根本原因，需要時請求技術服務中心或外部專家支援。
4. **調查、處理及改善報告**：完成損害控制或復原後**一個月內**提出，內容包括事件經過、影響範圍與損失、根因分析、處理過程、補強措施與預防再發生的改善計畫及期程；主管機關得要求說明或調整，並追蹤改善完成。
