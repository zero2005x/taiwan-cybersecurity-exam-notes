## 一、軟體定義網路（SDN）（28 分）

**題組敘述**：隨著 5G 時代的來臨，其所用的網路架構為軟體定義網路（Software Defined Networking, SDN），針對其網路架構及其可能遇到的威脅，請回答下列問題。

**整理者補寫**：SDN 是把網路設備的控制平面（決定封包怎麼走）與資料平面（實際轉送）分離，由集中式控制器以軟體掌握全網視野，透過南向介面（如 OpenFlow）下發流表到交換器，並以北向 API 讓應用程式依需求程式化地調整網路。優點是集中管理、快速部署政策、自動化與網路虛擬化；5G 核心網路與網路切片也運用 SDN／NFV 概念。

### （二）畫圖並詳述 SDN 架構（12 分）

**阿摩查核**：

- [申論頁 496177](https://yamol.tw/exam/116178?info=essay.496177)：nomi，2024-08-23，詳解 6197381，付費，已解鎖查核，有幫助 9／沒幫助 0

**題目**：(二)請畫圖並詳述 SDN 網路架構。（12 分）

**網友主解摘要與查核**：nomi 附架構圖並說明應用層、控制層、基礎設施層，正確，選為主解；缺南北向介面說明，以下補。

**整理者補寫**：

```text
 ┌──────────── 應用層 Application Layer ────────────┐
 │  網路應用：防火牆、負載平衡、路由、監控、編排      │
 └──────────────▲─────── 北向介面（REST API）────────┘
                │
 ┌──────────── 控制層 Control Layer ────────────────┐
 │  SDN 控制器（網路作業系統）：拓樸探索、路徑計算、  │
 │  流表管理、全網狀態（可叢集化備援）                │
 └──────────────▲─────── 南向介面（OpenFlow、NETCONF）┘
                │        東西向介面：控制器之間同步
 ┌──────────── 基礎設施層 Infrastructure Layer ─────┐
 │  OpenFlow 交換器／虛擬交換器：依流表比對、轉送、   │
 │  丟棄或回報封包                                    │
 └──────────────────────────────────────────────────┘
```

1. **應用層**：以程式表達業務需求（安全政策、流量工程），透過北向 API 向控制器下指令。
2. **控制層**：集中式控制器把需求轉成流表規則，維護全網拓樸與狀態；遇到無對應規則的封包時由交換器以 Packet-In 送交控制器決定。
3. **基礎設施層**：只負責高速轉送，依控制器下發的比對欄位與動作處理封包，並回報統計資訊。

## 二、政府零信任架構資源門戶部署的三大核心機制（24 分）

**阿摩查核**：

- [申論頁 496179](https://yamol.tw/exam/116178?info=essay.496179)：詳解 0、筆記 0、申論作答 0

**題目**：二、依據「國家資通安全發展方案（110 年至 113 年）」之「善用智慧前瞻科技、主動抵禦潛在威脅」推動策略，發展零信任架構資安防護環境，推動政府機關導入零信任架構，以完善政府網際服務網防禦深廣度。我國政府零信任架構係參考 NIST 零信任架構，同時結合向上集中之防護需求，採取資源門戶之部署方式。請列出並詳述此部署方式之三大核心機制。（24 分）

**整理者補寫**（本頁無網友詳解）：

我國政府依國家資通安全發展方案，參考 NIST SP 800-207，結合向上集中的防護需求，採「資源門戶（Resource Portal）」部署：使用者與設備須先經零信任閘道（政策執行點）驗證，通過後才能存取後端資源。三大核心機制：

1. **身分鑑別**：以多因子、抗釣魚的身分鑑別取代單純帳密，政府採 FIDO 標準（如自然人憑證、生物特徵結合裝置私鑰），並在鑑別後產出鑑別聲明（身分、方式、時間、強度），供信任推斷使用；每次存取都重新確認。
2. **設備鑑別**：以 TPM 等硬體保護的設備憑證證明設備身分，確認是機關納管設備；並進行設備健康管理，檢查作業系統修補、防毒或 EDR、組態基準（GCB）是否合規，不合規則拒絕或限縮存取。
3. **信任推斷**：政策引擎蒐集身分鑑別結果、設備狀態、使用者行為與情境（時間、地點、存取模式、威脅情資），以分數與規則計算信任等級，動態決定允許、要求追加驗證或拒絕，並在工作階段中持續評估、異常時中止連線。

三者依序導入，前兩者確認「誰」與「用什麼裝置」，第三者決定「此時此刻是否可信」，共同落實「永不信任、持續驗證」。

## 三、資安事故確認與回應（每小題 12 分，共 24 分）

**題組敘述**：學者 Pipkin 指出資安事故指標為有可能、極有可能、明確等三種不同類別，用以檢查某個事件是否成為一個可能的事故或稱為嫌疑事故（Incident Candidate）。

### （一）依資訊安全原則，列出至少三項並詳述如何確認發生真實資安事故

**阿摩查核**：

- [申論頁 496180](https://yamol.tw/exam/116178?info=essay.496180)：詳解 0、筆記 0、申論作答 0

**題目**：(一)依據資訊安全原則，請列出至少三項並詳述如何確認發生真實資安事故。

**整理者補寫**（本頁無網友詳解）：

Pipkin 把事故指標分為「可能（possible）」「極可能（probable）」「確定（definite）」。確認嫌疑事故是否為真實事故，可依資安原則逐項查證：

1. **機密性是否受損**：是否有未授權存取或資料外洩證據，例如異常帳號登入、大量下載、敏感檔案出現在外部、DLP 告警；查核存取日誌與外連流量。
2. **完整性是否受損**：系統檔、網頁、資料庫或設定是否遭未授權修改；以雜湊比對、檔案完整性監控、變更紀錄與版本差異確認。
3. **可用性是否受損**：服務中斷、效能異常、資料遭加密或刪除是否由惡意行為造成，而非硬體故障或正常維護；比對監控數據與變更排程。
4. **授權與政策違反**：是否有違反安全政策、未經授權的帳號、權限提升、未知程式或服務。
5. **確定性指標**：出現「確定」類指標即可直接認定，例如防護系統偵測到並確認的入侵、發現已知攻擊工具或後門、使用者帳號在不在場時被使用、主管機關或第三方通知外洩。

確認時應交叉比對多種來源（IDS、EDR、日誌、使用者回報），排除誤判，記錄判斷依據與時間，再依規定通報與分級。

## 四、弱點資訊與通報機制（每小題 12 分，共 24 分）

**題組敘述**：為防範各種不同的網路弱點及達到資安通報的機制，請回答下列問題。

### （一）CVE、NVD、CPE 的意義與彼此運作

**阿摩查核**：

- [申論頁 496182](https://yamol.tw/exam/116178?info=essay.496182)：詳解 0、筆記 0、申論作答 0

**題目**：(一)請詳述 CVE（Common Vulnerabilities and Exposures）、NVD（National Vulnerability Database）及 CPE（Common Platform Enumeration）之意義為何？並說明 CVE、NVD 及 CPE 彼此之間的運作情形。

**整理者補寫**（本頁無網友詳解）：

1. **CVE（Common Vulnerabilities and Exposures）**：由 MITRE 主導、各 CNA（CVE 編號機構）分配的公開弱點唯一識別碼，格式 CVE-年份-序號，附簡短描述與參考資料，讓各方以同一名稱指稱同一弱點。
2. **NVD（National Vulnerability Database）**：美國 NIST 維運的弱點資料庫，同步 CVE 清單並加值分析：CVSS 嚴重度分數、CWE 弱點類型、受影響產品（以 CPE 表示）、修補與參考連結。
3. **CPE（Common Platform Enumeration）**：以結構化命名描述資訊產品（廠商、產品、版本、平台），格式如 `cpe:2.3:a:apache:http_server:2.4.49:*:*:*:*:*:*:*`。
4. **運作關係**：發現弱點後由 CNA 指派 CVE ID 並公開；NVD 匯入該 CVE，評分並以 CPE 標記受影響產品版本；組織以自身資產清冊的 CPE 比對 NVD，即可自動找出哪些資產受哪些 CVE 影響，搭配 CVSS 排定修補優先順序。弱點掃描器與 SBOM 工具即利用此對應。

### （二）資通安全弱點通報機制（VANS）及其運作方法

**阿摩查核**：

- [申論頁 496183](https://yamol.tw/exam/116178?info=essay.496183)：詳解 0、筆記 0、申論作答 0

**題目**：(二)請詳述資通安全弱點通報機制（Vulnerability Alert and Notification System）及其運作方法。

**整理者補寫**（本頁無網友詳解）：

資通安全弱點通報機制（Vulnerability Alert and Notification System, VANS）由主管機關（行政院資安處推動，現由數位發展部資通安全署、國家資通安全研究院維運）建置，協助機關掌握資產弱點並及早修補：

1. **資產盤點**：機關以 CPE 格式登錄所使用的作業系統、應用程式與設備資訊（可由資產管理工具匯出上傳），建立資訊資產清冊。
2. **弱點比對**：系統定期將機關資產 CPE 與 NVD 等弱點資料庫的 CVE 比對，產出受影響資產與風險等級。
3. **通報與修補**：機關收到弱點清單後評估、修補或採取緩解措施，並在平台回報處理狀況；主管機關可掌握整體弱點修補進度並追蹤高風險弱點。
4. **持續管理**：資產異動時更新清冊，定期檢視修補成效；推動對象依責任等級逐步擴大（先 A、B 級機關）。

效益：從被動接收資安訊息轉為依實際資產主動預警，縮短弱點暴露時間，並提供跨機關弱點態勢。
