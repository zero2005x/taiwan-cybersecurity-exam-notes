**整理者作答**：
- **資訊長（CIO）**：負責組織資訊策略與資訊資源，使資訊科技支援並推動業務目標；規劃資訊架構與投資、督導系統開發與維運、預算與委外管理、推動數位轉型。需具備企業經營與策略規劃能力、資訊技術廣度、專案與變革管理、溝通協調與領導經驗，通常需多年資訊管理與業務歷練。
- **知識長（CKO）**：負責組織知識管理，促進知識的擷取、分享、保存與再利用，建立知識管理系統與學習型文化，將知識轉化為競爭優勢。需具備知識管理理論、組織行為與人力資源觀念、資訊系統（文件管理、協作平台）應用與跨部門溝通能力。
- **資訊安全長（CISO，題目寫為 CSIO）**：負責組織資訊安全治理與風險管理，訂定資安政策、規劃資安架構與預算、督導風險評鑑與控制措施、事件應變與通報、法規遵循（如《資通安全管理法》要求機關置資安長）、資安教育與稽核。需具備資安技術與管理知識（ISO/IEC 27001、NIST CSF）、法規與風險管理能力、危機處理與溝通能力，常需資安證照與實務經驗；並應具適當獨立性，可直接向最高管理階層報告。

**題目**（阿摩題文）：(一)傳統加密方法可分為取代法（Substitution）以及換位法（Transposition），請問著名的凱薩（Caesar）加密法是屬於那一種？回答時須附上正確的理由才予以計分。（5 分）
(二)請比較對稱式密鑰方法和非對稱式密鑰方法的特性與優缺點。（10 分）
(三) SSL（Secure Sockets Layer）安全協定是只利用對稱式密鑰方法，還是只利用非對稱式密鑰方法或是兩種方法都使用？回答時須附上正確的理由才予以計分。（10 分）

**網友主解摘要與查核**：（一）蟲不易版（付費已解鎖，有幫助 9）說明取代法與換位法並判定凱薩為取代法，正確，選為主解。（二）Phil 版（有幫助 6）表格稱非對稱式「安全性高」、對稱式「安全性較低」，以演算法安全性而言不精確（兩者安全性取決於金鑰長度與用法）；蟲不易版敘述非對稱流程有誤；Aaron Lim 版（有幫助 4）特性與優缺點正確完整，選為主解。（三）蟲不易版（有幫助 10）說明兩種都用，正確，選為主解；Phil 版（有幫助 5）稱「只用非對稱式」且流程描述錯誤，不可採。

**整理者作答**：

**（一）凱薩加密屬於哪一種（5 分）**：屬於**取代法**。凱薩加密把每個字母以字母表中固定位移後的字母取代（例如位移 3，A→D、B→E），字母本身被換掉但位置順序不變；換位法則是字母不變、只重新排列位置，因此凱薩加密不是換位法。

**（二）對稱式與非對稱式的比較（10 分）**

| 項目 | 對稱式 | 非對稱式 |
|---|---|---|
| 金鑰 | 加解密用同一把秘密金鑰 | 公鑰與私鑰一對，公鑰可公開 |
| 速度 | 快，適合大量資料 | 慢，適合少量資料與金鑰交換 |
| 金鑰分配 | 須事先以安全管道共享，n 人兩兩通訊需 n(n−1)/2 把 | 公鑰可公開分送，n 人需 n 對 |
| 功能 | 機密性 | 機密性、金鑰交換、數位簽章（鑑別、不可否認） |
| 例子 | AES、3DES | RSA、ECC |
| 優點 | 效率高、硬體易實作 | 解決金鑰分配問題、可提供簽章 |
| 缺點 | 金鑰分配與管理困難、無法提供不可否認性 | 運算量大，須以 PKI 確認公鑰屬誰 |

**（三）SSL 使用哪一種方法（10 分）**：**兩種都使用**（SSL 已淘汰，現行為 TLS，原理相同）。交握階段以非對稱式密碼學鑑別伺服器身分（憑證與數位簽章）並交換或協議工作階段金鑰（RSA 金鑰傳送或 Diffie-Hellman）；之後的資料傳輸以對稱式加密（如 AES）與訊息鑑別保護。理由：非對稱式可解決雙方事先沒有共享金鑰的問題，但速度慢；對稱式速度快，適合大量資料，因此採混合式設計。

**網友主解摘要與查核**：（一）Phil 版（付費已解鎖，有幫助 9）比較兩種防火牆優缺點，大致正確，選為主解。（二）Phil 版（有幫助 5、沒幫助 1）稱 Web 伺服器「不具有任何資料」「防火牆不需要檢視」等說法有誤；Aaron Lim 版（有幫助 5）說明隔離與降低風險，選為主解。（三）Phil 版（有幫助 7）稱 WAF「與病毒資料庫連線更新」，混淆防毒特徵與 WAF 規則，僅作參考，以下補寫 WAF 功能與特性。另有 Fisher 申論作答（付費未解鎖）。

**整理者作答**：

**（一）封包過濾與應用程式代理的特性與優缺點（10 分）**
- **封包過濾式**：在網路層、傳輸層依存取控制清單檢查每個封包的來源／目的 IP、埠號、協定與旗標，決定放行或丟棄。優點：速度快、成本低、對使用者透明。缺點：不檢查內容，無法辨識應用層攻擊；規則多時難管理；無狀態時易被偽造封包繞過；無使用者身分概念、日誌資訊有限。
- **應用程式代理**：在應用層作為中介，用戶端先連代理，代理檢查請求內容後再代為連線伺服器，內外部不直接連線。優點：可檢查應用層內容與指令、做身分鑑別與詳細記錄、隱藏內部主機。缺點：效能負擔大、延遲較高，每種協定需專屬代理程式，部分應用需設定用戶端，擴充性較差。

**（二）web 伺服器放在 DMZ 的理由（10 分）**：DMZ 是介於外網與內網之間、以防火牆隔離的區段。web 伺服器必須對網際網路開放，風險最高；放在 DMZ 可只開放外部到 web 伺服器的 80／443，同時禁止外部直接進入內網。即使 web 伺服器被入侵，攻擊者仍受防火牆限制，無法任意連到內部主機與資料庫（DMZ 到內網只開放必要的特定連線），降低擴散風險；把對外服務與內部資源分開，政策清楚、便於監控與稽核。若直接放在內網，被入侵即等於內網淪陷；若放在防火牆外則完全沒有保護。

**（三）WAF 的功能與特性（5 分）**：WAF 專門保護 Web 應用，部署在網站前端，解析 HTTP／HTTPS 請求與回應內容，阻擋 SQL Injection、XSS、命令注入、路徑遍歷等應用層攻擊；可做輸入驗證、速率限制與 Bot 防護、虛擬補丁，並記錄攻擊。特性：工作於第七層、以規則或學習建立正常行為模式、可部署為反向代理、雲端服務或伺服器模組，用以補足傳統防火牆看不到應用層內容的不足。

(二)請說明深偽技術（Deepfake）與核身（核對身分）注意事項。

**整理者作答**：

**（一）變臉詐騙與常見手法（15 分）**：變臉詐騙指詐騙者以 AI 換臉、變聲等深偽技術，在視訊或語音中冒充親友、主管、名人或公務人員，取得被害人信任後騙取金錢或資料。常見手法：（1）冒充親友視訊借錢或謊稱急難；（2）冒充主管或高階主管於視訊會議下令財務人員緊急匯款（深偽 BEC）；（3）冒用名人、專家影片推薦假投資平台；（4）假交友後以換臉視訊建立感情再借貸；（5）冒充檢警或銀行人員要求提供帳戶、驗證碼或監管帳戶；（6）合成私密影像勒索。共同特徵是製造急迫感、要求保密、要求改用其他通訊管道或特定帳戶付款。

**（二）深偽技術與核身注意事項（15 分）**：深偽（deepfake）是以深度學習（生成對抗網路、自編碼器、擴散模型等）合成或竄改影像、聲音，模仿特定人物的臉部表情、動作與聲紋。核身注意事項：
1. 涉及金錢、帳號或機密時，以事先已知的電話或管道回撥確認本人，不使用對方提供的聯絡方式。
2. 約定只有雙方知道的暗語或問題，詢問非公開資訊。
3. 視訊時請對方做出即時動作（轉頭側臉、以手遮臉、靠近鏡頭），觀察畫面延遲、邊緣模糊、光影不一致、眨眼與唇形不同步、聲音機械感。
4. 機構端線上核身應採多因子驗證與活體偵測（Liveness detection），結合裝置綁定、憑證或 FIDO，不單靠臉部或聲音比對；高風險交易加強驗證與延遲撥款。
5. 組織內建立匯款與敏感指示的雙人核准、書面流程；加強教育宣導，可疑情況撥打 165 反詐騙專線查證。

**整理者作答**：
1. **責任分擔模型不同**：內部部署由企業負責全部堆疊；雲端由業者負責底層實體與虛擬化，客戶仍負責資料、身分、存取與組態（IaaS 還包含作業系統）。風險在於誤以為雲端業者全包。控管：依服務型態（IaaS／PaaS／SaaS）釐清責任並寫入契約與 SLA，定期取得業者稽核報告（ISO/IEC 27001、27017、SOC 2）。

4. 其他差異：多租戶共享資源、資料駐地與法規管轄、對業者的依賴與可攜性、日誌與鑑識取得方式不同。控管：資料加密並自管金鑰（KMS／BYOK）、啟用雲端稽核日誌並集中到 SIEM、跨區備份與退場計畫。

## 114 年 二、以零信任強化遠端工作者保護及與 VPN 比較（25 分）

**阿摩查核**：

- [申論頁 546882](https://yamol.tw/exam/128310?info=essay.546882)：Aaron Lim，2025-07-11，詳解 6534596，標示由 GoogleAI 產生，付費，已解鎖查核，有幫助 10／沒幫助 0；申論作答 102052（mk010226，2026-08-01）

**題目**（阿摩題文）：二、請以零信任理念說明企業如何強化遠端工作者的資安保護，並分析相對於虛擬私人網路（Virtual Private Network, VPN）的優勢與風險。（25 分）

**網友主解摘要與查核**：Aaron Lim 版（GoogleAI 產生，有幫助 10）說明零信任實踐並比較 VPN，正確，選為主解；另有 mk010226 申論作答（付費未解鎖）。

**整理者作答**：

**零信任強化作法**：不因使用者在 VPN 內或在公司網路就信任，每次存取都依身分、裝置與情境驗證與授權（NIST SP 800-207）。
1. 身分：集中身分管理與 SSO，強制抗釣魚的多因子認證（FIDO2）。
2. 裝置：只允許已註冊、受 MDM 管理、修補與 EDR 正常的裝置；不合規則拒絕或只給受限存取。
3. 存取：以零信任網路存取（ZTNA）或身分感知代理，對每個應用個別授權，採最小權限，使用者看不到也連不到未授權的應用與網段。
4. 持續驗證：依地點、時間、行為與風險分數動態調整，異常時要求再驗證或中斷工作階段。
5. 監控與資料保護：集中記錄存取日誌、結合 DLP 與雲端存取安全代理（CASB）。

**相對於 VPN 的優勢**：VPN 驗證後通常讓使用者進入整個內網，帳密被盜或裝置中毒即可橫向移動；零信任按應用最小授權，縮小攻擊面與擴散範圍；不必把 VPN 閘道暴露在網際網路，避免成為漏洞攻擊目標；持續檢查裝置狀態；雲端服務可直接存取，不必繞回總部，效能與使用體驗較佳；細緻的日誌與可視性。

**零信任的風險與挑戰**：導入複雜，需盤點應用與資料流、整合身分與裝置管理；身分提供者成為關鍵單點，遭入侵或中斷影響全部存取；舊系統可能不支援現代驗證；政策設計錯誤可能過度開放或影響可用性；初期成本與人力需求高；使用者需適應。實務上常分階段導入，與 VPN 並存逐步汰換。

## 115 年 三、四種風險處理對策與實務範例（20 分）

**題目**（阿摩題文）：三、某政府機關正著手依據國際標準建立資訊安全管理系統（ISMS），以強化機關整體的資安防護。在推動過程中，必須落實風險評鑑與規範遵循。在資安風險處理（Risk Treatment）階段，組織通常有「風險降低（Mitigation）」、「風險迴避（Avoidance）」、「風險轉移（Transfer）」與「風險保持/接受（Retention/Acceptance）」四種對策。請詳述這四種對策的定義，並各舉一個資安實務上的應用範例。（20分）

**網友主解摘要與查核**：本頁無詳解，只有 mk010226 的申論作答（已解鎖查核），四種對策定義與範例正確，作為參考；以下整理者補寫。

**整理者作答**（ISO/IEC 27001、27005）：
1. **風險降低（Mitigation／Modification）**：導入或強化控制措施，降低風險發生的可能性或衝擊。例：針對帳號遭盜風險導入多因子認證與帳號鎖定；針對勒索軟體部署 EDR 與離線備份。
2. **風險迴避（Avoidance）**：停止或不進行造成風險的活動，或改變做法以消除風險來源。例：決定不在對外網站保存民眾身分證影像；停用已停止支援且無法修補的舊系統功能。
3. **風險轉移（Transfer／Sharing）**：把部分風險的財務後果或處理責任轉給第三方。例：購買資安保險；委託具 ISO 27001 驗證的雲端或資安監控服務，並在契約訂定賠償與責任（注意法定責任與機關督導責任不會因此轉移）。
4. **風險保持／接受（Retention／Acceptance）**：在風險低於可接受準則或處理成本高於效益時，經權責主管正式核定後承擔該風險並持續監控。例：內部非機敏、低使用量系統的低風險弱點，經評估暫不修補而列入風險清冊定期複審。

處理後應評估剩餘風險，記錄於風險處理計畫與適用性聲明，並持續監督。

## 115 年 四、IAM 中 MFA、零信任與 IAAA（30 分）

**阿摩查核**：

- [申論頁 582451](https://yamol.tw/exam/142291?info=essay.582451)：申論作答 101683（mk010226，2026-07-30）
- [申論頁 582452](https://yamol.tw/exam/142291?info=essay.582452)：mk010226，2026-07-30，詳解 7463612，標示由 ChatGPT 產生，免費公開，有幫助 0／沒幫助 0

**題目**（阿摩題文）：(一)請詳細說明 IAM 系統中的「多因素認證（MFA）」與「零信任（Zero Trust）」模型這兩項機制將如何發揮作用，以有效阻斷駭客在竊取密碼後的後續登入與系統擴張行為？（15 分）
(二)請問 IAAA 的四個核心分別代表什麼？如何運作以降低資安風險？（15 分）

**網友主解摘要與查核**：（一）只有 mk010226 申論作答（已解鎖查核），以 MFA 阻斷密碼外洩登入、零信任阻斷橫向擴張說明，正確，作為參考；（二）mk010226 免費詳解（ChatGPT 產生）說明 IAAA 四核心，選為主解。

**整理者作答**：

**（一）MFA 與零信任如何阻斷竊密後的登入與擴張（15 分）**：
- **MFA**：要求「所知」以外的「所持」或「所具」因子（手機推播、硬體金鑰、生物特徵），駭客只拿到密碼仍無法通過登入；採 FIDO2 等抗釣魚方法，可防止中間人代理網站轉送驗證碼；推播加上號碼比對，避免 MFA 疲勞轟炸。
- **零信任**：登入成功不代表取得整個網路的信任。每次存取資源都再依身分、裝置健康與情境評估（持續驗證），異常地點、不合規裝置或行為異常時要求再驗證或拒絕；以最小權限與微分段，讓帳號只能存取執行職務所需的應用與資料，攻擊者無法以單一帳號橫向移動或提升權限；特權帳號採即時（JIT）授權與工作階段監控；所有存取紀錄集中分析，可迅速偵測並撤銷遭盜用的工作階段。

**（二）IAAA 的四個核心與運作（15 分）**：
1. **識別（Identification）**：使用者宣稱自己是誰，例如輸入帳號、員工編號；每人唯一帳號、不共用。
2. **鑑別（Authentication）**：驗證宣稱的身分是否屬實，以密碼、憑證、生物特徵等因子，重要系統採多因子。
3. **授權（Authorization）**：依身分、角色（RBAC）或屬性（ABAC）決定可存取哪些資源與可執行哪些動作，落實最小權限與職務分離。
4. **稽核或問責（Auditing／Accountability）**：記錄誰在何時做了什麼，保護日誌完整性並定期審查，使行為可追溯、可究責。

四者依序運作：先識別與鑑別確認「是誰」，再依授權決定「能做什麼」，最後以稽核留下證據並發現異常；搭配帳號生命週期管理（到職、異動、離職即時調整）與定期權限審查，降低冒用、越權與內部濫用的風險。
