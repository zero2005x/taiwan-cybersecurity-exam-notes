## 112 年 一、零信任安全模型及其基本原則（25 分）

**阿摩查核**：

- [申論頁 503481](https://yamol.tw/exam/117985?info=essay.503481)：Aaron Lim，2023-12-13，詳解 5983846，付費，已解鎖查核，有幫助 8／沒幫助 0

**題目**（阿摩題文）：一、請說明何謂零信任安全模型（Zero Trust Security Model）？並請條列說明該模型的 5 項基本原則。（25 分）

**網友主解摘要與查核**：只有 Aaron Lim版（有幫助 8），說明「永不信任、總是驗證」並列最小權限等五項原則，正確，選為主解。

**整理者作答**：零信任安全模型以「永不信任、始終驗證」為核心，不因使用者、裝置或流量位於內部網路就自動信任，將防護重心從網路邊界轉移到個別資源，每次存取都依身分、裝置狀態與情境進行驗證與授權，並假設網路已遭入侵（NIST SP 800-207）。五項基本原則（條列）：
1. **明確驗證**：每次存取都以所有可用資料（身分、位置、裝置健康、服務或工作負載、資料分類、異常）進行驗證與授權，採多因子認證。
2. **最小權限存取**：只給完成工作所需的最小權限，採即時（JIT）與足夠（JEA）權限，降低帳號被盜時的損害。
3. **假設已遭入侵**：以微分段縮小攻擊範圍，端對端加密，持續監控以快速偵測與回應。
4. **以資源為中心、逐次授權**：所有資料與服務都視為資源，存取以每個工作階段為單位授權，網路位置不代表信任。
5. **動態政策與持續監控**：存取政策依使用者、裝置、行為等屬性動態決定；持續收集資產、網路與存取狀態資訊並改善安全態勢。

## 112 年 二、身分驗證與授權的區別及例子（25 分）

**阿摩查核**：

- [申論頁 503482](https://yamol.tw/exam/117985?info=essay.503482)：Aaron Lim，2023-12-13，詳解 5983852，付費，已解鎖查核，有幫助 7／沒幫助 0

**題目**（阿摩題文）：二、請說明身分驗證（Authentication）和授權（Authorization）的區別，並各提供身分驗證和授權的兩個實際例子。（25 分）

**網友主解摘要與查核**：只有 Aaron Lim 版（有幫助 7），區分驗證與授權並舉密碼登入、指紋與存取權限例子，正確，選為主解。

**整理者作答**：
- **身分驗證（Authentication）**：確認「你是誰」，驗證使用者宣稱的身分是否真實，依據所知（密碼、PIN）、所持（手機、智慧卡、硬體金鑰）、所具（指紋、臉部）等因子。例：（1）登入公務系統時輸入帳號密碼，再以手機 App 推播確認（多因子）；（2）以自然人憑證晶片卡加 PIN 碼登入報稅網站。
- **授權（Authorization）**：在身分確認後決定「你能做什麼」，依角色、屬性或政策授予可存取的資源與操作權限。例：（1）人事系統中一般員工只能查看自己的薪資，人事人員才能修改全體資料（RBAC）；（2）雲端檔案分享設定某人對資料夾僅有「檢視」權限而不能編輯或下載。
- **區別**：驗證在前、授權在後；驗證回答身分真偽，授權回答權限範圍；驗證失敗無法進入系統，授權不足則能登入但無法執行特定動作；驗證常用 MFA、OAuth/OIDC 登入，授權常用存取控制清單、RBAC／ABAC、OAuth 2.0 權杖範圍。兩者都要配合稽核紀錄，落實最小權限。

## 113 年 三、中間人攻擊的方法與防範（25 分）

**阿摩查核**：

- [申論頁 528695](https://yamol.tw/exam/124355?info=essay.528695)：一起撐住一起上榜，2025-06-26，詳解 6507247，標示由 ChatGPT 產生，付費，已解鎖查核，有幫助 10／沒幫助 0

**題目**（阿摩題文）：三、請說明何謂中間人攻擊（Man-in-the-Middle Attack），並舉例說明兩種不同中間人攻擊的方法。當面對中間人攻擊的威脅時，請說明可行的防範作法。（25 分）

**網友主解摘要與查核**：一起撐住一起上榜版（ChatGPT，付費已解鎖，有幫助 10）說明 MITM 並舉 ARP 欺騙與偽造憑證兩種方法及防範，正確，選為主解。

**整理者作答**：中間人攻擊是攻擊者秘密介入通訊雙方之間，雙方以為直接通訊，實際上所有訊息經攻擊者轉送，攻擊者可竊聽、竄改或冒充。兩種方法舉例：
1. **ARP 欺騙**：在區域網路中送出偽造的 ARP 回應，把閘道器 IP 對應到攻擊者的 MAC，受害者送往外部的流量都先經過攻擊者。
2. **惡意 Wi-Fi 熱點（Evil Twin）**：架設與合法熱點同名的基地台，使用者連上後所有流量都經攻擊者，再搭配 SSL Stripping 將 HTTPS 降級成 HTTP 或假冒登入頁竊取帳密。
（其他：DNS 欺騙、偽造憑證、BGP 劫持、瀏覽器中間人惡意程式。）
**防範作法**：全面使用 TLS 並啟用 HSTS，嚴格檢查憑證，不忽略瀏覽器警告；行動 App 採憑證釘選；在公共 Wi-Fi 使用 VPN；交換器啟用動態 ARP 檢測與 DHCP Snooping，靜態 ARP 綁定重要主機；DNSSEC 與加密 DNS；Wi-Fi 使用 WPA3／802.1X；重要交易使用多因子與交易簽章；教育使用者辨識假熱點與假網站。

## 113 年 四、對稱與非對稱式加密、公鑰憑證與 PKI（25 分）

**阿摩查核**：

- [申論頁 528696](https://yamol.tw/exam/124355?info=essay.528696)：一起撐住一起上榜，2025-06-26，詳解 6507248，標示由 ChatGPT 產生，付費，已解鎖查核，有幫助 9／沒幫助 0

**題目**（阿摩題文）：四、密碼學在資通安全扮演極為重要的角色，請比較對稱式密鑰和非對稱式密鑰兩種加密方法的優缺點，並說明非對稱式密鑰須使用公鑰憑證（public key certificate）的理由。公鑰憑證要由 PKI （Public Key Infrastructure）提供，請說明 PKI 之意義與功用。（25 分）

**網友主解摘要與查核**：一起撐住一起上榜版（ChatGPT，付費已解鎖，有幫助 9）比較對稱與非對稱式並說明公鑰憑證與 PKI，正確，選為主解。

**整理者作答**：
1. **優缺點比較**：對稱式（AES）加解密使用同一把金鑰，優點是速度快、適合大量資料，缺點是金鑰須事先安全分享、數量隨參與者平方成長、無法提供不可否認性；非對稱式（RSA、ECC）使用公鑰與私鑰，優點是公鑰可公開、解決金鑰分配並能數位簽章，缺點是運算慢、金鑰較長。實務上混合使用（如 TLS）。
2. **為何須使用公鑰憑證**：非對稱式密碼的安全前提是「這把公鑰確實屬於對方」。若攻擊者以自己的公鑰冒充他人，就能解讀加密給對方的訊息或偽造簽章（中間人攻擊）。公鑰憑證由可信的第三方憑證機構以數位簽章把持有者身分與公鑰綁在一起，並註明效期與用途，讓使用者可驗證公鑰的歸屬。
3. **PKI 的意義與功用**：公開金鑰基礎建設是發行、管理、驗證、撤銷公鑰憑證所需的軟硬體、人員、政策與程序的整體架構，包括憑證機構（CA）、註冊機構（RA）、憑證儲存庫、憑證撤銷清單（CRL）與線上狀態查詢（OCSP）、憑證政策與實務作業基準。功用：鑑別身分（HTTPS 網站、自然人憑證）、數位簽章與不可否認性、加密金鑰交換、完整性保護，建立陌生雙方之間的信任鏈。

## 114 年 一、SDN 在企業資安架構的應用與兩個實例（25 分）

**阿摩查核**：

- [申論頁 560129](https://yamol.tw/exam/134657?info=essay.560129)：Aaron Lim，2025-12-09，詳解 7214977，標示由 GoogleAI 產生，付費，已解鎖查核，有幫助 3／沒幫助 0；Yuchang Wu，2026-01-08，詳解 7274107，付費，已解鎖查核，有幫助 5／沒幫助 0

**題目**（阿摩題文）：一、軟體定義網路（Software-Defined Networking）是一種新型態網路架構，該架構可使網路管理員在不更動硬體裝置的前提下，以中央控制方式用程式重新規劃網路，為控制網路流量提供了新方案，也為核心網路和應用創新提供了良好平台。請說明軟體定義網路在企業資訊安全架構中的應用場景，並舉出兩個實際案例說明其如何進行資訊安全的防護能力提升及可能成效。（25 分）

**網友主解摘要與查核**：Yuchang Wu 版（付費已解鎖，有幫助 5）列應用場景並以分公司伺服器中毒隔離等兩例說明，選為主解；Aaron Lim 版（GoogleAI，有幫助 3）擬答架構完整，可作補充。

**整理者作答**：SDN 將控制平面集中於控制器，可透過程式即時調整全網轉送規則，在資安上的應用場景包括：動態隔離受感染主機、微分段與零信任存取、依威脅情資即時下發阻擋規則、把可疑流量導向 IDS／沙箱等安全服務鏈、DDoS 偵測與流量清洗導流、全網流量可視化與異常偵測。
1. **實例一：自動隔離受感染主機**：EDR 或 IDS 偵測到某主機與 C2 通訊後，透過 API 通知 SDN 控制器，控制器立即對該主機所連交換器埠下發流表，將其流量導入隔離 VLAN 或只允許連到修補伺服器。成效：從偵測到遏制由人工數小時縮短到秒級，阻止勒索軟體橫向擴散。
2. **實例二：微分段與資料中心東西向防護**：在資料中心或校園以 SDN 依應用與身分定義白名單政策，例如只允許 Web 伺服器連到特定資料庫埠，其餘東西向流量全部拒絕。成效：大幅縮小攻擊面，入侵單一主機也難以擴散；政策集中管理、變更快速並可稽核。
（另可舉：偵測到 DDoS 時控制器將攻擊流量導向清洗設備。）需同時保護控制器本身（高可用、TLS、存取控制），避免成為單點攻擊目標。

## 114 年 三、零信任下內部人員濫權的原因與控管（25 分）

**阿摩查核**：

- [申論頁 560131](https://yamol.tw/exam/134657?info=essay.560131)：Aaron Lim，2025-12-16，詳解 7259865，標示由 GoogleAI 產生，付費，已解鎖查核，有幫助 2／沒幫助 0；Yuchang Wu，2026-01-08，詳解 7274104，付費，已解鎖查核，有幫助 4／沒幫助 0

**題目**（阿摩題文）：三、零信任架構（Zero Trust Architecture）是一種網路安全模型，其核心理念是永不信任，始終驗證。某企業已導入零信任架構卻仍遭內部人員濫權存取資料，請分析此類內部信任濫用的潛在原因，並提出有效控管機制以強化零信任防禦深度。（25 分）

**網友主解摘要與查核**：Yuchang Wu 版（付費已解鎖，有幫助 4）列過度授權、缺乏持續驗證、IAM 與監控未整合等原因與控管，選為主解；Aaron Lim 版（GoogleAI，有幫助 2）指出 ZTA 未涵蓋授權範圍內的異常行為，觀點正確，可作補充。

**整理者作答**：
**潛在原因**：零信任多著重驗證「是不是本人」與裝置是否合規，而濫權者本身就是合法使用者、使用合規裝置；權限設定過大或未依職務異動即時調整（權限蔓延）；缺乏資料層級的細緻授權與用途限制；特權帳號常駐、共用帳號；缺少行為分析，只看登入時的信任評分而未持續評估存取模式；日誌未定期審查或管理者可自行刪除日誌；職務分離不足；組織文化與教育不足、離職前或心懷不滿員工的風險未被注意。
**控管機制**：
1. 最小權限與定期權限審查，到職、調職、離職流程與身分管理系統連動，即時調整權限。
2. 資料分級與以屬性為基礎的存取控制（ABAC），依業務關係與用途授權；敏感資料遮罩，大量查詢或下載需額外核准。
3. 特權存取管理（PAM）：即時授權、雙人核准、工作階段錄影，禁止共用帳號。
4. 使用者與實體行為分析（UEBA）持續評估存取行為，異常（大量下載、非上班時間、存取非職務資料）即時告警或要求再驗證、中止工作階段。
5. 資料外洩防護（DLP）、浮水印與 USB、雲端上傳管控。
6. 日誌集中、不可竄改並定期稽核，職務分離（管理者不能審查自己的紀錄）。
7. 簽署保密協定、教育與內部舉報機制，人事風險管理。

## 114 年 四、異常偵測在 NIDS 的應用、優點、誤判原因與對策（25 分）

**阿摩查核**：

- [申論頁 560132](https://yamol.tw/exam/134657?info=essay.560132)：Aaron Lim，2025-12-16，詳解 7259869，標示由 GoogleAI 產生，付費，已解鎖查核，有幫助 2／沒幫助 0；Yuchang Wu，2026-01-08，詳解 7274111，付費，已解鎖查核，有幫助 3／沒幫助 0

**題目**（阿摩題文）：四、異常偵測（Anomaly Detection）是一種資料分析技術，可用以識別資料中不尋常的模式。請說明異常偵測在網路入侵偵測系統中的應用原理和兩個優點，並說明異常偵測誤判原因和降低其誤判率的對策。（25 分）

**網友主解摘要與查核**：Yuchang Wu 版（付費已解鎖，有幫助 3）說明基線建模、零時差偵測等兩項優點與誤判對策，選為主解；Aaron Lim 版（GoogleAI，有幫助 2）內容相近。

**整理者作答**：
1. **應用原理**：先在學習期收集正常網路行為建立基準（流量大小、連線數、協定比例、連線時間與對象、封包特徵），以統計方法、機器學習或規則描述正常輪廓；偵測期將即時流量與基準比較，偏離超過門檻（例如某主機突然大量對外連線、出現新協定或非上班時間大量傳輸）即視為異常並告警。
2. **兩個優點**：（1）不需事先知道攻擊特徵，可偵測零時差攻擊與新型、變種攻擊；（2）能發現內部人員濫用、帳號被盜後的異常行為與慢速、隱蔽的資料外洩等不符合特徵規則的威脅。
3. **誤判原因**：正常行為本身會變化（新系統上線、業務尖峰、備份作業、軟體更新）；學習期資料不足或已含攻擊流量，使基準不正確；門檻設定不當；特徵選擇不佳；網路環境複雜、加密流量看不到內容；攻擊者刻意緩慢改變行為讓模型學成正常。
4. **降低誤判對策**：以足夠長且乾淨的資料建立基準，並定期重新訓練；依時段、主機角色分群建立多個基準；調整門檻並以白名單排除已知正常活動；結合特徵偵測、威脅情資與資產資訊做關聯分析（SIEM），多重證據才升級告警；分析師回饋標記誤報以調校模型；告警分級處理。
