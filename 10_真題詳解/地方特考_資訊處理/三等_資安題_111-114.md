**題目**（阿摩題文）：(一)何謂生物辨識技術？列舉至少五種生物辨識技術，並依安全性（Security）和方便性（Convenience）等級（假設分 3 級：優、良、普）做論述。（20 分）
(二)目前手機的認證大部分是利用何種生物辨識技術？它有何優缺點？（5 分）

**網友主解摘要與查核**：（一）Phil 版（付費已解鎖，有幫助 10）列五種技術並評比，選為主解，但其把聲紋列為安全性「優」、列入「血液辨識」（非常見生物辨識技術），評比有待商榷，以下以虹膜、靜脈、指紋、臉部、聲紋重新評比。（二）Phil 版（有幫助 5）列手機臉部與指紋辨識的優缺點，選為主解；「個人資料保護較不足」宜具體說明為生物特徵無法更換，以下補正。

**整理者作答**：

**（一）生物辨識技術與安全性、方便性評比（20 分）**：生物辨識是以人的生理特徵或行為特徵自動辨識或驗證身分，屬於「所具之物」的鑑別因子，不會遺忘或遺失；流程為註冊時擷取特徵建立樣板，驗證時比對樣板與即時擷取的特徵，以錯誤接受率（FAR）與錯誤拒絕率（FRR）衡量。評比（優／良／普，屬一般性判斷，實際依產品與活體偵測能力而異）：

| 技術 | 安全性 | 方便性 | 說明 |
|---|---|---|---|
| 虹膜辨識 | 優 | 良 | 紋理複雜穩定、FAR 極低；需專用攝影機與配合注視 |
| 指靜脈／掌靜脈 | 優 | 良 | 特徵在皮下、難以複製；需專用感測器 |
| 指紋辨識 | 良 | 優 | 成本低、普及；可能被殘留指紋或假指模仿，手指受傷潮濕影響 |
| 人臉辨識 | 良（3D 結構光為優、2D 為普） | 優 | 非接觸、速度快；易受光線、化妝、雙胞胎、照片或深偽影響 |
| 聲紋辨識 | 普 | 優 | 可遠端使用；易受感冒、噪音影響，且可被錄音或語音合成冒用 |
| 簽名動態／步態／擊鍵 | 普 | 良 | 行為特徵會變動，多作為輔助或持續驗證 |

**（二）手機常用的生物辨識與優缺點（5 分）**：主要是**指紋辨識**（電容式、屏下光學或超音波）與**人臉辨識**（3D 結構光如 Face ID，或 2D 影像）。優點：解鎖快速方便，生物特徵樣板只存在手機安全晶片中、不上傳，可作為 FIDO 無密碼登入的本機驗證。缺點：2D 人臉可能被照片欺騙；指紋可被假指紋或趁睡眠時冒用；手指潮濕、戴口罩影響辨識；生物特徵無法更換，一旦外洩終身無效；法律上可能被強迫解鎖，因此重要場合仍應搭配 PIN 碼。

## 111 年資訊管理與資通安全 四、量子電腦及其對密碼學的影響（25 分）

**阿摩查核**：

- [申論頁 481264](https://yamol.tw/exam/112357?info=essay.481264)：Phil(112高普雙榜)，2022-12-16，詳解 5681049，付費，已解鎖查核，有幫助 10／沒幫助 0

**題目**（阿摩題文）：四、2022 年諾貝爾物理學獎由法國學者阿斯佩（Alain Aspect)、美國學者克勞澤(John F. Clauser)以及奧地利學者塞林格(Anton Zeilinger)共同獲得，表揚他們發現量子糾纏（Quantum Entanglement）並打下了量子電腦、量子密鑰系統的基礎，確立了可違反貝爾不等式，和開創性的量子通訊科學。何謂量子電腦？它對目前資安的密碼學有何影響？(25 分)

**網友主解摘要與查核**：Phil 版（付費已解鎖，有幫助 10）說明量子疊加與對暴力破解的影響，選為主解，但未區分 Shor 演算法對 RSA／ECC 的致命影響與 Grover 對對稱式的平方根加速，以下補正並列後量子密碼因應。

**整理者作答**：
1. **量子電腦**：以量子位元（qubit）運算的電腦。量子位元可處於 0 與 1 的疊加態，多個量子位元可透過糾纏形成關聯，運算時以量子干涉放大正確答案的機率。對特定問題（大數分解、離散對數、搜尋、量子模擬）可比傳統電腦有指數或平方級加速；目前仍處於含雜訊的中等規模（NISQ）階段，錯誤率與量子位元數是主要限制。
2. **對公開金鑰密碼的影響**：Shor 演算法可在多項式時間內分解大整數與解離散對數，足夠大的容錯量子電腦將能破解 RSA、Diffie-Hellman、ECC（ECDH、ECDSA），使 TLS 金鑰交換、數位簽章、PKI 憑證全面失效。攻擊者可先截取並保存現在的加密流量，待量子電腦成熟後再解密（先竊取、後解密），長期機密資料已面臨風險。
3. **對對稱式與雜湊的影響**：Grover 演算法使暴力搜尋只需約平方根次數，等效安全強度減半；AES-128 降為約 64 位元等級，因此建議改用 AES-256、SHA-384 以上即可維持安全。
4. **因應**：（1）遷移至後量子密碼（PQC）：NIST 已於 2024 年發布 FIPS 203（ML-KEM，金鑰封裝）、FIPS 204（ML-DSA）、FIPS 205（SLH-DSA）（屬考試後的發展）；（2）盤點系統中使用的密碼演算法與憑證（密碼清冊），規劃遷移優先順序，過渡期採混合式金鑰交換；（3）設計密碼敏捷性（crypto-agility），便於替換演算法；（4）量子金鑰分發（QKD）以物理原理分享金鑰，可作為特定場域的補充，但有距離與成本限制。

**網友主解摘要與查核**：河馬王版（免費，有幫助 5）說明利用未修補漏洞與防毒、最小權限、使用習慣，正確但簡略；一起撐住一起上榜版（ChatGPT，付費已解鎖，有幫助 2）列發生時機、危機與 EDR、沙箱、虛擬補丁等因應，較完整，選為主解。

**整理者作答**：
1. **發生時機**：在漏洞已被攻擊者發現並利用，但軟體廠商尚未知悉、或已知悉但尚未釋出修補程式（修補「零天」）的期間；也包括廠商已發布修補但使用者尚未安裝的「N-day」空窗期。漏洞生命週期：漏洞產生 → 攻擊者發現並開發利用程式 → 攻擊發生 → 廠商得知 → 發布修補 → 使用者部署修補。
2. **資安危機**：沒有修補程式與特徵碼，防毒、IDS 難以偵測；常被 APT 與國家級攻擊者用於針對性入侵、植入後門、竊取機密；對外服務（VPN、郵件伺服器、防火牆）的零時差漏洞可被大量掃描利用，造成勒索軟體與資料外洩；修補前只能靠緩解措施，影響範圍大且難以評估。
3. **因應**：
   - 預防：縮小攻擊面（關閉不必要服務與對外介面）、最小權限、應用程式白名單、網路分段；安全開發與第三方元件管理。
   - 偵測：EDR／XDR 行為偵測、沙箱分析、異常流量與日誌監控、威脅獵捕，訂閱威脅情資與廠商安全公告。
   - 應變：廠商發布前先採緩解（停用功能、調整設定、IPS／WAF 虛擬補丁、限制來源 IP）；發布後依風險優先快速修補並驗證；依事件應變程序隔離受害主機、通報與鑑識；平時備份與演練以縮短復原時間。

**題目**（阿摩題文）：(一)相較於 4G，5G 行動網路的特點有那些？請詳細說明之。
(二)企業採用 5G 行動專網帶來的安全風險有那些？請條列並說明之。

**網友主解摘要與查核**：（一）只有 Aaron Lim版（有幫助 10），說明速度、延遲、連接數，正確，選為主解，以下補三大應用情境與核心網路架構。（二）Aaron Lim 版（有幫助 8）列攻擊面、供應鏈、切片隔離、隱私；一起撐住一起上榜版（有幫助 2）列設備接入、攔截、切片、核心網、基地台。選 Aaron Lim 版為主解，兩者合併補寫。

**整理者作答**：

**（一）相較於 4G 的特點（10 分）**：ITU 定義的三大應用情境：（1）增強型行動寬頻（eMBB），峰值速率可達 20 Gbps，約為 4G 的數十倍；（2）超高可靠度低延遲通訊（URLLC），空中介面延遲可低至 1 毫秒，適合自駕車、遠端醫療、工業控制；（3）大規模機器型通訊（mMTC），每平方公里可連接約百萬個裝置，支撐物聯網。架構上採服務化核心網路（SBA）、網路功能虛擬化（NFV）與軟體定義網路（SDN），支援網路切片、邊緣運算（MEC），並使用毫米波等更高頻段；安全上強化以 SUCI 隱藏使用者永久身分、改良的 5G-AKA 驗證與家用網路確認。

**（二）企業採用 5G 專網的安全風險（10 分）**：
1. **軟體化與虛擬化風險**：核心網路為軟體與容器化元件，有一般 IT 的軟體漏洞、組態錯誤與供應鏈風險。
2. **網路切片隔離不足**：與公網或其他租戶共用基礎設施時，切片隔離失效可能導致資料外洩或資源被耗盡。
3. **大量 IoT 終端**：終端安全能力低、預設密碼、韌體難更新，易被入侵成為跳板或殭屍網路，甚至偽冒 SIM 卡接入。
4. **邊緣運算節點**：部署在廠區，實體安全與管理不如機房，可能被竄改或成為入侵點。
5. **開放介面與 API**：SBA 以 HTTP／2 API 互通，API 認證授權不當可被濫用；與 IT／OT 網路互連增加橫向移動風險。
6. **委外與維運**：系統由電信業者或整合商建置維運，遠端維護通道與責任分界不清；設備供應鏈的可信度問題。
7. **無線干擾與 DoS**：干擾訊號、偽基地台、信令風暴影響可用性。
因應：網路分段與切片隔離、零信任存取、SIM／終端身分鑑別、API 安全與最小權限、持續監控與弱點管理、明確的委外資安責任。

**題目**（阿摩題文）：(一)何謂 Zone file？請說明其用途及內容。（5 分）
(二)請說明迭代式 DNS 查詢（iterative DNS query）的工作原理。（10 分）
(三)當 SOC（Security Operation Center）對受管理組織下某台主機發出「DNS Open Resolver 弱點」的告警訊息時，代表後者可能存在的資安危害為何？請說明之。（5 分）

**網友主解摘要與查核**：（一）Aaron Lim 版（有幫助 10）說明 Zone file 用途與紀錄類型，選為主解，未提 SOA 紀錄，以下補足。（二）Aaron Lim 版（有幫助 6）說明由根、TLD 到權威伺服器的迭代過程，正確，選為主解；一起撐住一起上榜版稱「DNS Resolver 不代為查完整過程」，把迭代與遞迴的角色說反，不採。（三）Aaron Lim 版（有幫助 7）與一起撐住一起上榜版（有幫助 2）皆指出放大攻擊與快取投毒，選 Aaron Lim 版為主解。

**整理者作答**：

**（一）Zone file 的用途與內容（5 分）**：Zone file 是權威 DNS 伺服器上描述一個區域（zone）所有資源紀錄的文字檔，用以回應該網域的查詢與提供區域傳送。內容包括：`$ORIGIN`、`$TTL` 指令；SOA 紀錄（主要名稱伺服器、管理者信箱、序號、更新、重試、過期與負面快取時間）；NS 紀錄；A、AAAA、CNAME、MX、TXT、PTR、SRV 等紀錄。

**（二）迭代式 DNS 查詢的原理（10 分）**：被詢問的伺服器不代為查到底，而是回覆「我知道的最好答案或下一個該問的伺服器」，由詢問者自行一步步追問。例如遞迴解析器查 `www.example.com.tw`：先問根伺服器，根回覆 `.tw` 的 TLD 伺服器清單；再問 `.tw` 伺服器，回覆 `com.tw` 或 `example.com.tw` 的權威伺服器（NS 與 glue）；最後問權威伺服器取得 A 紀錄。解析器並依 TTL 快取結果。用戶端對解析器多為遞迴查詢，解析器對各層伺服器則為迭代查詢。

**（三）DNS Open Resolver 弱點代表的資安危害（5 分）**：該主機的 DNS 服務對任何網際網路來源提供遞迴查詢。危害：（1）被利用為 DNS 反射放大攻擊的放大器，攻擊者偽造受害者 IP 送出小查詢（如 ANY），主機回應大量資料給受害者，使組織成為 DDoS 共犯並耗盡自身頻寬；（2）易遭快取投毒（cache poisoning），讓使用者被導向惡意網站；（3）資源被外部濫用、洩漏內部查詢資訊。應限制遞迴查詢只服務內部網段、啟用回應速率限制（RRL）與 DNSSEC 驗證。

**整理者作答**：

**（一）DMZ 的用意（5 分）**：以防火牆在外網與內網之間隔出的網段，放置必須對外服務的主機（Web、郵件、DNS）。只開放外部到 DMZ 的必要服務，並嚴格限制 DMZ 到內網的連線，即使 DMZ 主機被攻破，攻擊者也難以直接進入內網，達到分區防護與縱深防禦。

**整理者作答**：

**（一）SQL 注入與常見案例（15 分）**：應用程式把使用者輸入直接串接到 SQL 指令中執行，攻擊者在輸入中加入 SQL 語法改變查詢邏輯，可繞過驗證、讀取或竄改資料、刪除資料表，甚至透過資料庫功能執行系統指令。案例：（1）登入繞過：帳號輸入 `admin' --` 或 `' OR '1'='1`，使 `SELECT * FROM users WHERE id='...' AND pw='...'` 條件恆真；（2）UNION 注入：在搜尋參數加入 `' UNION SELECT username, password FROM users --` 竊取其他資料表；（3）盲注：依頁面真假差異或回應延遲（`SLEEP(5)`）逐字推出資料；（4）堆疊查詢：`'; DROP TABLE orders; --`；（5）實際事件中常見於網站會員資料大量外洩、網頁置換。

**（二）預備語句能防止 SQL 注入的原因與原理（10 分）**：預備語句（參數化查詢）先把含佔位符的 SQL 範本（如 `SELECT * FROM users WHERE id = ? AND pw = ?`）送交資料庫編譯並決定執行計畫，之後才把使用者輸入以參數值綁定傳入。資料庫把參數一律當成資料值處理，不會重新解析為 SQL 語法，因此輸入中的引號、`OR`、`--` 只會成為字串內容，無法改變查詢結構。注意：資料表名、欄位名、ORDER BY 等無法參數化的部分仍需白名單驗證；預存程序內若動態串接 SQL 同樣有風險；應搭配最小權限、輸入驗證與錯誤訊息隱藏。

**題目**（阿摩題文）：(1)該辦法將資通系統防護需求等級分為那幾級？
(2)對防護需求為中級之資通系統在存取控制構面下之帳號管理、識別與鑑別構面下之身分驗證管理需執行的防護措施有那些？

**網友主解摘要與查核**：（1）Aaron Lim 版（有幫助 8、沒幫助 1）把資通系統防護需求等級答成 A 至 E 級，錯誤（那是機關資通安全責任等級）；Eyrk 版稱分五級「特高、高、中、低、基礎」也錯誤；rdice001 版（付費已解鎖，有幫助 9）指正應為高、中、普三級，選為主解。（2）Aaron Lim 版（有幫助 8）列帳號管理與身分驗證措施，大致正確，選為主解，但其把定期審核、閒置帳號等列為中級要求，須對照當時附表十確認；Eyrk 版內容與附表十不符。以下依修正對照表的「現行規定」欄整理。

**整理者作答**：依考試時（113 年）《資通安全責任等級分級辦法》附表九、附表十：

1. **防護需求等級**：依資通系統在機密性、完整性、可用性、法律遵循性四構面的影響程度，分為**普、中、高**三級，任一構面為高即列高級，否則任一構面為中即列中級，其餘為普級。
2. **中級系統之帳號管理（存取控制構面）**：
   - 普級事項：建立帳號管理機制，包含帳號之申請、建立、修改、啟用、停用及刪除之程序。
   - 中級另應：已逾期之臨時或緊急帳號應刪除或禁用；資通系統閒置帳號應禁用；定期審核資通系統帳號之申請、建立、修改、啟用、停用及刪除。
   - （高級再加上：定義閒置時間或可使用期限，逾越時系統自動登出；依機關規定之情況及條件使用資通系統；監控帳號違常使用並回報管理者。）
3. **中級系統之身分驗證管理（識別與鑑別構面）**：
   - 普級事項：使用預設密碼登入者，應於登入後要求立即變更；身分驗證相關資訊不以明文傳輸；具備帳戶鎖定機制，帳號登入進行身分驗證失敗達五次後，至少十五分鐘內不允許該帳號繼續嘗試登入，或使用機關自建之失敗驗證機制；基於密碼之鑑別資通系統應強制最低密碼複雜度，強制密碼最短及最長之效期限制；使用者更換密碼時，至少不可以與前三次使用過之密碼相同。
   - 中級另應：身分驗證機制應防範自動化程式之登入或密碼更換嘗試；密碼重設機制對使用者重新身分確認後，發送一次性及具有時效性符記。
（上述已對照資安署分級辦法修正對照表中的「現行規定」欄核對。修正後將逾期帳號、閒置帳號、定期審核下移為普級，閒置時間自動登出移為中級，現行規定應另行查核。）

## 114 年資通網路與安全 三、SSDLC 開發流程與效益（25 分）

**阿摩查核**：

- [申論頁 559775](https://yamol.tw/exam/134567?info=essay.559775)：Aaron Lim，2025-12-09，詳解 7214883，標示由 GoogleAI 產生，付費，已解鎖查核，有幫助 7／沒幫助 0；申論作答 28874（考取中華電地特三等聯招，2026-04-27）

**題目**（阿摩題文）：三、為提升資通訊系統之安全性，某政府組織導入 SSDLC（Secure Software Development Life Cycle）。請說明 SSDLC 之開發流程，並說明其效益。（25 分）

**網友主解摘要與查核**：Aaron Lim 版（GoogleAI 產生，有幫助 7）依需求、設計、開發、測試、部署維運說明 SSDLC 與效益，正確，選為主解。另有申論作答 1 份（付費未解鎖）。

**整理者作答**：
1. **流程**（把安全納入 SDLC 各階段，可參考 NIST SP 800-218 SSDF、OWASP SAMM 與資通系統防護基準的「系統與服務獲得」構面）：
   - 需求階段：依系統防護需求等級訂定安全需求（身分鑑別、存取控制、加密、日誌、個資保護、法規），進行風險評估。
   - 設計階段：威脅建模（如 STRIDE）、安全架構設計（最小權限、縱深防禦、預設安全）、安全設計審查。
   - 開發階段：安全程式撰寫規範（輸入驗證、參數化查詢、輸出編碼）、開發人員教育、靜態原始碼檢測（SAST）、第三方元件與開源授權管理（SCA、SBOM）。
   - 測試階段：弱點掃描、動態應用程式測試（DAST）、滲透測試（中、高級系統）、安全功能測試，修補後複測。
   - 部署與維運：安全組態設定、上線前檢核、修補與弱點管理、監控與日誌、事件應變、變更管理；委外開發要求安全性檢測證明。
   - 汰除：資料移轉、清除與媒體銷毀。
2. **效益**：在早期發現並修正弱點，大幅降低修補成本（越晚修補成本越高）；減少上線後遭攻擊與資料外洩；符合《資通安全管理法》與防護基準要求，提升稽核通過率；建立可重複的安全開發流程與文件；提升委外品質與供應鏈安全；增加民眾與使用者信任。

## 114 年資通網路與安全 四、降低雲端資安風險措施與公有雲、私有雲的資安管理差異（25 分）

**阿摩查核**：

- [申論頁 559776](https://yamol.tw/exam/134567?info=essay.559776)：Aaron Lim，2025-12-09，詳解 7214896，標示由 GoogleAI 產生，付費，已解鎖查核，有幫助 5／沒幫助 0；申論作答 28876（考取中華電地特三等聯招，2026-04-27）

**題目**（阿摩題文）：四、某組織規劃將資訊系統遷移至公有雲平台。搬遷前應評估資安風險，並採取必要措施以降低資安風險。請說明降低雲端資安風險之措施，並比較公有雲和私有雲在資安管理之差異性。（25 分）

**網友主解摘要與查核**：Aaron Lim 版（GoogleAI 產生，有幫助 5）說明責任分擔模型與降低雲端風險措施，選為主解。另有申論作答 1 份（付費未解鎖）。

**整理者作答**：

**降低雲端資安風險的措施**：
1. 搬遷前評估：資料分級（機敏、個資、公務機密是否適合上公有雲），依《政府機關雲端服務應用資安參考指引》等規定評估；選擇通過 ISO/IEC 27001、27017、27018 或 CSA STAR 的業者，確認資料存放地點。
2. 契約與責任：明訂責任分擔、SLA、資安事件通報時限、稽核權、資料返還與刪除、退場機制。
3. 身分與存取：所有帳號 MFA，最小權限 IAM，根帳號保護、特權帳號管理。
4. 資料保護：傳輸與靜態加密，自管金鑰（KMS／HSM），備份與跨區複寫。
5. 組態與網路：安全基準與 CSPM 持續檢查組態，私有子網路與安全群組最小開放，WAF 與 DDoS 防護。
6. 監控與應變：啟用雲端稽核日誌並集中到 SIEM／SOC，弱點掃描與修補，演練雲端事件應變。

**公有雲與私有雲的資安管理差異**：

| 面向 | 公有雲 | 私有雲 |
|---|---|---|
| 責任 | 共同責任，底層由業者負責，客戶負責資料、身分、組態 | 組織自行負責全部或大部分 |
| 控制程度與可視性 | 對底層實體與虛擬化層控制有限，依賴業者報告與 API 日誌 | 可完全掌控硬體、網路與稽核 |
| 多租戶風險 | 與其他客戶共用資源，需依賴隔離技術 | 單一組織專用 |
| 資料駐地與法規 | 須確認儲存地與跨境傳輸規定 | 自行決定、較易滿足機敏資料規範 |
| 主要風險 | 組態錯誤、帳號金鑰外洩、業者中斷、廠商綁定 | 自建能力與成本、修補維運負擔、規模與備援不足 |
| 資安能力 | 可利用業者大規模的安全服務與專業團隊 | 依組織資源與人力而定 |

**題目**（阿摩題文）：四、身為政府機關資訊安全專責人員，當接獲軟體委外廠商通報發生資安事件時，請問依照資通安全事件通報及應變辦法，您該如何處理？（25 分）

**網友主解摘要與查核**：Yuchang Wu 版（付費已解鎖，有幫助 8）依評估、通報（1 小時內）、應變、復原與報告說明，正確，選為主解；Aaron Lim 版（GoogleAI，有幫助 7、沒幫助 1）引用條次較多，可作補充。

**整理者作答**：依考試時《資通安全事件通報及應變辦法》（114 年時之規定，依法修正後條次可能變動）與委外契約處理：
1. **確認與記錄**：接獲受託廠商通報後，記錄通報時間（即「知悉」時點）、事件經過、受影響系統與資料、廠商已採取的措施，必要時要求廠商提供日誌與證據。
2. **初判等級並通報**：依事件影響的機密性、完整性、可用性，以及是否涉及核心業務、核心資通系統、公務機密或個資，判定為第一至第四級；於知悉後 **1 小時內**透過主管機關指定的通報應變網站（無法上網時以其他適當方式）向上級或監督機關通報，內容包括機關名稱、聯絡人、事件發生時間與知悉時間、事件經過、影響範圍與等級、已採取措施等；同時向機關資安長報告，第三、四級事件由資安長督導應變。
3. **應變處置**：要求廠商配合並自行啟動應變小組；第一、二級事件於知悉後 **72 小時內**、第三、四級事件於 **36 小時內**完成損害控制或復原作業，並依規定時限通知上級或監督機關；處置包括隔離受害系統、停用遭盜帳號與廠商遠端存取、保全證據、修補與清除、由備份復原；必要時請求上級機關或主管機關技術支援。
4. **後續報告與檢討**：於完成損害控制或復原後 **1 個月內**送交調查、處理及改善報告，內容包括事件經過、根因分析、影響、補強措施與預防再發生之改善；依個資法通知受影響當事人。
5. **委外管理**：依契約追究廠商責任，檢討受託者資安措施，必要時進行稽核、要求改善或終止契約；更新委外資安要求與風險評估，並將事件納入教育訓練與演練。
