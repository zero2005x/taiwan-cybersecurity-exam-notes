# 112 年高考二級資訊處理：資訊管理與資通安全研究

查核日：2026-10-11。題文見[試題轉錄](../../11_公職特考與高考二級_資安科目_試題/高考二級_資訊管理與資通安全研究_111-115.md#112年)，官方原卷見[考選部 PDF](https://wwwq.moex.gov.tw/exam/wHandExamQandA_File.ashx?t=Q&code=112160&c=224&s=1009&q=1)。四題均收：第三題比較容器與虛擬主機，隔離程度與安全直接相關，列為邊緣題。各頁有 Aaron Lim 與 shang 的免費詳解。非官方標準答案。

## 一、禁止以生成式 AI 製作機密文書的原因（24 分）

**阿摩查核**：

- [申論頁 498502](https://yamol.tw/exam/116717?info=essay.498502)：Aaron Lim，2023-10-15，詳解 5947315，付費，已解鎖查核，有幫助 0／沒幫助 0；shang，2024-09-30，詳解 6219630，付費，已解鎖查核，有幫助 5／沒幫助 0

**題目**：一、「行政院及所屬機關（構）使用生成式 AI 參考指引」，其中第三點：「製作機密文書應由業務承辦人親自撰寫，禁止使用生成式 AI。」請就資安保密、責任歸屬、技術風險、法律合規等面向說明應如此限制的原因？（24 分）

**網友主解摘要與查核**：shang 版（有幫助 5）從資料傳送至外部伺服器、責任模糊、模型輸出不準確、個資與著作權合規說明，正確，選為主解。Aaron Lim 版把「訓練資料含機密遭駭」列為主要保密風險，未切中「輸入內容外洩」的重點。

**整理者補寫**：指引由國科會研擬，112 年 8 月 31 日提報行政院院會，第三點規定製作機密文書應由業務承辦人親自撰寫，禁止使用生成式 AI。

1. **資安保密**：使用雲端生成式 AI 時，輸入內容會傳送並可能留存於境外第三方伺服器，或被用於模型訓練、遭供應商人員存取、因服務遭入侵而外洩；機密一旦輸入即失去控制，違反「知所必需」原則。提示注入、對話紀錄外洩等新型攻擊也可能把內容帶出。
2. **責任歸屬**：機密文書涉及判斷與決策，須由具權責的承辦人負責；AI 產出的內容來源不明，出錯時難以釐清是工具、使用者或審核者的責任，也不符公文分層負責與保密責任。
3. **技術風險**：模型會產生幻覺、錯誤或偏差內容，且無法說明依據；可能夾帶過時或他人資料；輸出不穩定，不適合用於高度精確、不可出錯的機密文件。
4. **法律合規**：違反《國家機密保護法》、《公務員服務法》保密義務及機關機密維護規定；涉及個資時違反《個人資料保護法》的目的外利用與安全維護義務；跨境傳輸與供應商資料處理條款難以符合；產出內容也可能侵害著作權。

## 二、零信任的白話比喻與三大關鍵技術（24 分）

**阿摩查核**：

- [申論頁 498503](https://yamol.tw/exam/116717?info=essay.498503)：Aaron Lim，2023-10-15，詳解 5947316，付費，已解鎖查核，有幫助 0／沒幫助 0；shang，2024-09-30，詳解 6219357，付費，已解鎖查核，有幫助 2／沒幫助 0

**題目**：二、「零信任架構」（Zero Trust Architecture）是一種概念，請用最簡單白話的方式或比喻描述這個概念究竟是什麼？實施重點有身分鑑別、設備鑑別及信任推斷三大關鍵技術，請加以說明？（24 分）

**網友主解摘要與查核**：shang 版定義零信任並詳細說明身分鑑別（MFA、鑑別聲明）、設備鑑別（TPM、健康管理）、信任推斷，對應政府架構，正確，選為主解；但缺題目要求的白話比喻。Aaron Lim 版以「拆掉城牆、每區都有守衛」比喻，可補上。

**整理者補寫**：

1. **白話比喻**：傳統資安像有圍牆的城堡，進了大門就能在城內自由走動；零信任像一棟每個房間都有門禁的大樓——不論你是員工還是訪客、從哪個門進來，每次要進任何一間房，都要刷證件（身分）、確認你帶的東西是合格的（設備），警衛還會看你當下的行為是否異常（情境），而且只開你被授權的那一間門。也就是「永不預設信任，每次都驗證」。
2. **身分鑑別**：以多因子、抗釣魚的 FIDO 技術確認使用者身分，產生鑑別聲明（誰、用什麼方式、何時通過）供存取決策使用。
3. **設備鑑別**：以 TPM 保護的設備憑證確認是機關納管裝置，並持續檢查設備健康狀態（修補、防毒、組態），不合規即降權或拒絕。
4. **信任推斷**：政策引擎綜合身分、設備狀態、使用者行為與情境（時間、地點、存取模式）計算信任分數，動態決定是否允許存取，並在使用期間持續重新評估。

## 三、容器與虛擬主機的差異（28 分）

**阿摩查核**：

- [申論頁 498504](https://yamol.tw/exam/116717?info=essay.498504)：Aaron Lim，2023-10-15，詳解 5947320，付費，已解鎖查核，有幫助 4／沒幫助 0；shang，2024-09-30，詳解 6219705，付費，已解鎖查核，有幫助 1／沒幫助 0

**題目**：三、容器和虛擬主機是兩種不同的虛擬化技術，請說明它們的運作上的隔離程度、資源需求、啟動速度、部署管理等差異？（28 分）

**網友主解摘要與查核**：Aaron Lim 版（有幫助 4）以表格比較四面向，方向正確但較簡略；shang 版說明 Hypervisor、Namespace、Cgroups、啟動流程與編排工具，技術細節更完整。為完整作答選 shang 版為主解。

**整理者補寫**：

| 面向 | 虛擬主機（VM） | 容器（Container） |
|---|---|---|
| 運作方式 | Hypervisor（Type 1 或 Type 2）模擬硬體，每台 VM 有完整的客體作業系統與核心 | 共用主機作業系統核心，以 namespace 隔離程序、網路、檔案系統，以 cgroups 限制資源 |
| 隔離程度 | 強：硬體虛擬化邊界，單一 VM 遭入侵不易影響他者（仍有 VM escape 風險） | 較弱：共用核心，核心漏洞或錯誤設定（特權容器、掛載主機目錄）可能導致容器逃逸；可用 seccomp、AppArmor／SELinux、rootless、gVisor／Kata 加強 |
| 資源需求 | 高：每台需完整 OS，占用 GB 級記憶體與儲存 | 低：映像只含應用與相依函式庫，MB 級，密度高 |
| 啟動速度 | 慢：需開機載入核心與服務，數十秒至數分鐘 | 快：即啟動程序，毫秒至數秒 |
| 部署管理 | vCenter、Hyper-V 等管理，適合長期運作、異質作業系統、傳統應用 | 映像版本化、一次建置到處執行，搭配 Kubernetes 編排自動擴展、滾動更新，適合微服務與 CI/CD |
| 安全管理重點 | 修補客體與 Hypervisor、VM 範本強化 | 映像弱點掃描與簽章、最小基礎映像、不以 root 執行、網路政策、Secrets 管理 |

實務上常兩者併用：在 VM 上運行容器，取得 VM 的強隔離與容器的部署效率。

## 四、造成機密性、完整性、可用性危害的攻擊（24 分）

**阿摩查核**：

- [申論頁 498505](https://yamol.tw/exam/116717?info=essay.498505)：Aaron Lim，2023-10-15，詳解 5947322，付費，已解鎖查核，有幫助 4／沒幫助 0；shang，2024-10-01，詳解 6220210，付費，已解鎖查核，有幫助 0／沒幫助 0

**題目**：四、請分別針對機密性、完整性、可用性，舉例說明有那些惡意行為或攻擊會造成這三類危害？（24 分）

**網友主解摘要與查核**：Aaron Lim 版評價較高（有幫助 4），但把 DDoS 列為完整性攻擊，分類錯誤；shang 版（有幫助 0）以竊聽、社交工程、惡意軟體；中間人、SQL 注入、DNS 偽造；SYN flood、UDP flood、勒索軟體分類，正確且舉例具體。依正確性選 shang 版為主解。

**整理者補寫**：

1. **機密性**：網路竊聽與封包側錄、釣魚與社交工程騙取帳密、間諜軟體或鍵盤側錄、SQL 注入竊取資料庫、權限提升或越權存取（IDOR）、內部人員外洩、雲端儲存設定錯誤公開、勒索集團竊取後外洩（雙重勒索）。
2. **完整性**：中間人攻擊竄改傳輸內容、網頁置換、SQL 注入修改或刪除資料、DNS 快取汙染導向假網站、竄改日誌湮滅證據、供應鏈植入惡意更新、偽造交易或訊息（BEC 改帳號）。
3. **可用性**：DDoS（SYN flood、UDP 放大、HTTP flood）、勒索軟體加密資料與系統、刪除或抹除資料（wiper）、資源耗盡（邏輯炸彈、fork bomb）、破壞實體設備或電力、針對 DNS 或 BGP 的劫持使服務無法連線。

同一攻擊可能同時影響多項，例如勒索軟體同時危害可用性（加密）與機密性（外洩）。
