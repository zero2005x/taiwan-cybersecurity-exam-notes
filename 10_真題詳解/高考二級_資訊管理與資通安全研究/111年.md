# 111 年高考二級資訊處理：資訊管理與資通安全研究

查核日：2026-10-11。題文見[試題轉錄](../../11_公職特考與高考二級_資安科目_試題/高考二級_資訊管理與資通安全研究_111-115.md#111年)，官方原卷見[考選部 PDF](https://wwwq.moex.gov.tw/exam/wHandExamQandA_File.ashx?t=Q&code=111160&c=222&s=0909&q=1)。本卷只收資安相關的第一、四題；第二題（機器學習）與第三題（政府資訊公開）不屬資安題，不做詳解。非官方標準答案。

## 一、數位轉型的定義與資安風險及防護（25 分）

**阿摩查核**：

- [申論頁 475452](https://yamol.tw/exam/110947?info=essay.475452)：Phil(112高普雙榜)，2022-11-12，詳解 5656202，付費，已解鎖查核，有幫助 9／沒幫助 0

**題目**：一、請說明數位轉型（Digital Transformation）的定義，並詳述推動數位轉型時可能面臨的資安風險及相對應的防護措施。（25 分）

**網友主解摘要與查核**：Phil 版（有幫助 9）以新技術零時差、與舊策略不一致、測試資料外洩等面向說明，但定義偏狹、風險面向不完整（缺雲端、IoT、遠距、供應鏈），所舉「舊規定比新規定嚴格」例子也非一般性風險。選為唯一主解，以下重寫。

**整理者補寫**：

1. **定義**：數位轉型是組織運用雲端、行動、大數據、AI、IoT 等數位科技，重新設計業務流程、服務模式、組織文化與決策方式，以創造新價值與提升競爭力；不只是把紙本電子化（數位化），而是以資料驅動的營運與服務變革。
2. **資安風險與對應防護**：

| 風險 | 說明 | 防護措施 |
|---|---|---|
| 攻擊面擴大 | 對外 API、行動 App、雲端服務、IoT 設備增加入侵點 | 資產盤點與攻擊面管理、API 閘道與鑑別、定期弱點掃描與滲透測試 |
| 雲端設定錯誤與責任不清 | 儲存桶公開、權限過大、誤以為安全全由雲端廠商負責 | 共同責任模型、CSPM 組態檢查、最小權限 IAM、日誌集中監控 |
| 身分與遠距存取 | 遠距辦公、SaaS 普及，帳密成為主要攻擊目標 | MFA、SSO、零信任存取、裝置管理 |
| 資料外洩與個資風險 | 資料大量集中、跨系統串接與分析 | 資料分類分級、加密、DLP、去識別化、個資保護影響評估 |
| 供應鏈與委外 | 大量採用第三方平台、開源元件、委外開發 | 委外資安要求與稽核、SBOM、程式碼檢測、供應商風險評估 |
| IT／OT 整合 | 工控與 IoT 連網後暴露 | 網段隔離、OT 監控、韌體更新管理 |
| 新技術風險 | AI 模型遭投毒、提示注入、資料濫用 | AI 治理、模型與資料存取控制、輸出審查 |
| 人員與流程 | 員工資安意識不足、變革速度快於管控 | 教育訓練、安全開發生命週期（SSDLC）、DevSecOps、事件應變演練 |

推動時應採「Security by Design」，把資安納入轉型規劃初期，並以風險評估決定優先順序。

## 四、靜態與動態程式碼檢測的實務做法與比較（25 分）

**阿摩查核**：

- [申論頁 475455](https://yamol.tw/exam/110947?info=essay.475455)：信心，2022-10-06，詳解 5627724，付費，已解鎖查核，有幫助 3／沒幫助 1；Phil(112高普雙榜)，2022-11-14，詳解 5657447，付費，已解鎖查核，有幫助 7／沒幫助 0

**題目**：四、請分別詳述利用靜態分析（Static Analysis）及動態分析（Dynamic Analysis）進行程式碼檢測（Code Testing）的實務做法並比較這兩種檢測方式的優缺點。（25 分）

**網友主解摘要與查核**：Phil 版（有幫助 7）把靜態分析描述為人工文件審查、動態分析描述為單元測試，偏軟體品質觀點，未涵蓋資安檢測工具（SAST、DAST）；信心版只有兩句定義。選 Phil 版為主解，以資安觀點重寫。

**整理者補寫**：

1. **靜態分析（SAST）實務**：不執行程式，直接分析原始碼、位元組碼或二進位檔。做法：在 IDE 與 CI/CD 流程整合 SAST 工具（如 SonarQube、Checkmarx、Fortify、Semgrep），依規則集（OWASP Top 10、CWE、機關安全程式碼規範）掃描資料流與污點傳遞，找出 SQL 注入、XSS、寫死密碼、不安全函式、緩衝區溢位；人工程式碼審查（code review）複核；搭配 SCA 檢查第三方元件已知漏洞；設定品質門檻，高風險未修不得合併或上線。
2. **動態分析（DAST）實務**：在測試環境部署可執行的系統，從外部以攻擊者角度送出請求。做法：以 OWASP ZAP、Burp Suite 等工具爬取並攻擊 Web 與 API，模糊測試（fuzzing）、身分驗證與授權測試、滲透測試；也可使用 IAST（在執行中植入探針）結合兩者；對結果驗證、排除誤判並追蹤修補。
3. **比較**：

| 面向 | 靜態分析 | 動態分析 |
|---|---|---|
| 時機 | 開發早期即可，左移、修補成本低 | 需可執行版本，通常在測試或上線前 |
| 需求 | 需原始碼（或二進位） | 不需原始碼（黑箱） |
| 涵蓋 | 可涵蓋所有程式路徑，能指出問題程式行號 | 只測到實際執行到的路徑，無法直接定位程式碼 |
| 可發現問題 | 程式碼缺陷、不安全寫法、寫死機密 | 執行期問題：組態錯誤、鑑別與 Session 管理、伺服器設定、第三方整合 |
| 誤判 | 誤報率較高，需人工篩選 | 誤報較少，但可能漏報 |
| 限制 | 依語言與框架支援、難判斷執行環境 | 需完整環境、測試時間長，可能影響系統 |

兩者互補，資安檢測應結合 SAST、SCA、DAST 與人工滲透測試，納入安全軟體開發生命週期。
